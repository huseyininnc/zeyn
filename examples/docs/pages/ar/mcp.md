# MCP ووكلاء الذكاء الاصطناعي

صُمم Zeyn للوكلاء من جهتين: وكلاء يكتبون تطبيقات Zeyn، ووكلاء يستخدمون تطبيقاً قيد التشغيل نيابةً عن مستخدم.

## الوكلاء الذين يكتبون التطبيقات

يحمل المشروع الذي يعمل فيه الوكيل قواعده وأدواته:

- يسرد `AGENTS.md` و`CLAUDE.md` الأوامر وبنية المشروع وقواعد اللغة وفهرساً للإطار.
- يسجّل `.mcp.json` الأمر `zeyn mcp`، وهو خادم MCP عبر stdio بهذه الأدوات:

| الأداة | ما تفعله |
|---|---|
| `zeyn_docs` | مرجع الإطار حسب الموضوع: `rules` و`language` و`protocol`؛ `search: "كلمات"` يرتّب صفحات التوثيق لهذا الإصدار، و`page: "/language/forms"` يعيد صفحة بصيغة Markdown |
| `zeyn_describe` | ميزات التطبيق وشاشاته ومساراته وصلاحيات الوصول وواجهات API والمشكلات والترجمات الناقصة |
| `zeyn_inspect` | شجرة عُقد شاشة واحدة: المسار ونوع المكوّن و`file:line:column` في Rust الذي وضع كل عقدة |
| `zeyn_check` | يصرّف الشيفرة ويبلّغ عن المشكلات؛ و`fix: true` يعيد أولاً كتابة واجهات API التي تغيّرت أسماؤها |
| `zeyn_test` | يشغّل `cargo test` ويعيد نهاية المخرجات |
| `zeyn_new_feature` | ينشئ مجلد ميزة ويسجّلها |
| `zeyn_new_screen` | يضيف ملف شاشة إلى ميزة ويسجّله |

المترجم هو الحارس الرئيسي. لكل قاعدة يستطيع فرضها اختبار `compile_fail` ورسالة `#[diagnostic::on_unimplemented]` مكتوبة ليتصرف الوكيل بناءً عليها، مثل:

```sh
error[E0277]: `min()` and `max()` cannot be used on a `bool` column
  = note: `min()` and `max()` work on i32, i64, Money, Date, Time, DateTime, LocalDateTime and their Option forms
```

يطبع `ZEYN_DESCRIBE=1 cargo run` الوصف نفسه الذي تعيده `zeyn_describe` ثم ينتهي.

### Source inspector

تتذكر بنيات التصحيح سطر Rust الذي وضع كل عقدة على الشاشة (`Screen::body` و`Stack::add` و`Tabs::tab` وبقية دوال الحاويات). يطبع `ZEYN_INSPECT=<screen> cargo run` شجرة العُقد التي تعيدها `zeyn_inspect` ثم ينتهي.

بنية التصحيح التي تُخدَّم بـ `cargo run` تكتب السطر في الصفحة بوصفه `data-zeyn-src` على أول عنصر لكل عقدة. يفتح Alt+Shift+I طبقة تحدد العقدة تحت المؤشر أو العنصر الذي عليه التركيز وتذكر سطره، ثم أسطر العُقد التي تحتويه؛ ويغلقها Alt+Shift+I أو Escape. بنيات الإصدار لا تحفظ أي سطر: تبقى العقدة مؤشرًا واحدًا في صندوق، ولا تحمل الصفحة أي سمة، ولا يكون سكربت الفحص داخل الملف التنفيذي.

## الوكلاء الذين يستخدمون تطبيقاً

```rust
App::new(t!("app.name")).mcp(Mcp::read_only())
```

مع `agents` تصبح شاشات التطبيق أدوات:

- أداة بحث واحدة لكل جدول،
- أداة حفظ واحدة لكل نموذج، وتكون حقول النموذج وقواعده هي مخططها (فقط مع `Mcp::read_write()`).

يصل الوكلاء إليها بطريقتين:

- **في المتصفح** عبر WebMCP (`document.modelContext.registerTool`)، عندما يدعمه المتصفح. تُسجَّل أدوات الشاشة الحالية عند فتحها وتُزال عند إغلاقها.
- **على الخادم** عند `POST /_zeyn/mcp` (JSON-RPC). يحتاج إلى ترويسة `Authorization`، لذلك لا يمكن لجلسة متصفح وحدها أن تشغّله أبداً.

## القواعد نفسها التي تنطبق على الناس

- يحصل الوكيل على صلاحيات المستخدم الذي يعمل نيابةً عنه بالضبط. لا تُدرج الأدوات الخاصة بالشاشات والإجراءات التي لا يحق للمستخدم فتحها.
- تمر الاستدعاءات عبر الحراس (guards) والمعترضات (interceptors) والتحقق وحدود المعدل الخاصة بالاستدعاء العادي.
- تعلّم سجلات التدقيق الاستدعاءات التي أجراها الوكلاء، ليتمكن المراجع من التمييز بينها.
- يتيح `Mcp::read_only()` للوكلاء البحث دون الحفظ. اختر `read_write()` فقط للتطبيقات التي ينبغي فيها أن يغيّر الوكيل البيانات.
