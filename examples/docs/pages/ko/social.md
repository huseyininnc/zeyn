# 소셜

소셜 페이지를 위한 컴포넌트입니다. 각 컴포넌트는 서버에서 렌더링되며, 해당 컴포넌트를 사용하는 페이지에서만 스타일시트와 스크립트를 불러옵니다.

## StoryRing

`StoryRing`은 어떤 사람의 스토리가 보는 사람에게 새로운지 알려 주는, 링 안의 아바타입니다. `StoryState::Unseen`은 브랜드 색의 두꺼운 링을, `StoryState::Seen`은 얇은 중립색 링을 그립니다. 상태는 서버에서 오며, 앱이 보는 사람에 대해 저장해 둔 값에서 정해집니다. 브라우저는 이를 바꾸지 않습니다. `StoryRow`는 링을 레일처럼 옆으로 스크롤되는 한 줄에 배치합니다.

```rust
StoryRow::new()
    .add(StoryRing::new(ada.name.clone(), StoryState::Unseen)
        .image(ada.photo.clone())
        .link(stories, StoryParams { person: ada.id }))
    .add(StoryRing::new(alan.name.clone(), StoryState::Seen).image(alan.photo.clone()))
```

`.link(screen, params)`를 지정하면 링은 스토리를 보여 주는 화면으로 가는 링크가 됩니다. 접근 가능한 이름은 사람의 이름과 상태이며, 예를 들어 "Ada Lovelace, 읽지 않은 스토리"와 같습니다. 링 아래에 보이는 이름도 같은 방식으로 시작하므로 음성 제어 사용자가 그대로 말할 수 있습니다. 두 상태는 색뿐 아니라 링의 두께로도 구분되며, 강제 색상 모드에서는 본 링이 점선으로 그려집니다. 이미지는 `Avatar` 규칙을 따릅니다(앱의 경로 또는 허용된 `https` 주소). 이미지가 없으면 이니셜이 표시됩니다.

링은 CSS만으로 그려집니다. 스크립트도 이미지도 없습니다. `stories.css`(2.2 KB)는 링이 있는 페이지에서만 불러옵니다. 한 줄에는 최대 `MAX_STORY_RINGS`(100)개의 링이 들어갑니다. 터치, 트랙패드, Shift+휠로 스크롤할 수 있고, 링은 제자리에 맞춰 멈추며, 키보드 포커스를 받은 링은 보이는 영역으로 스크롤됩니다. 한 줄의 링 중 링크가 있는 것이 없으면 줄 자체가 포커스를 받으므로 키보드로 계속 스크롤할 수 있습니다.

| 키 | 동작 |
|---|---|
| Tab | 다음 링으로 이동하고 보이는 영역으로 스크롤합니다 |
| Enter | 포커스된 링의 스토리를 엽니다 |
| Left, Right | 줄 자체에 포커스가 있을 때: 줄을 스크롤합니다 |


## Lightbox

모든 `Image`는 `.lightbox()`로 전체 화면으로 열 수 있습니다. 화면이 허용하는 만큼 크게 이미지를 보여 주고 캡션과 확대 기능을 갖춘 모달 대화상자입니다. `.full(src)`는 lightbox가 보여 줄 더 큰 파일을 지정하며 페이지는 작은 파일을 그대로 유지합니다. `.caption(text)`는 그 아래에 캡션을 붙입니다(둘 다 lightbox를 켭니다). `.video(source, file)`는 이미지를 미디어 소스의 동영상 포스터로 만들고, lightbox가 그 동영상을 재생합니다. 한 게시물의 이미지나 `Row`, `Stack`, `AutoGrid` 같은 한 컨테이너의 이미지는 한 묶음이 되며, 화살표 키와 스와이프로 그 사이를 이동합니다.

```rust
AutoGrid::new().min(140)
    .add(Image::new(p.thumb.clone()).alt(p.title.clone()).size(300, 300)
        .full(p.photo.clone())
        .caption(p.title.clone()))
    .add(Image::new(clip.poster.clone()).alt(clip.title.clone()).size(320, 180)
        .video("films", clip.file.clone()))
```

스크립트가 없으면 이미지는 자기 파일로 연결되는 링크이므로 그래도 열립니다. 스크립트가 있으면 `lightbox.js`(13 KB, gzip 4.4 KB)와 `lightbox.css`(4 KB)는 lightbox 이미지가 있는 페이지에서만 로드되고, 대화상자는 처음 열릴 때 만들어집니다. 대화상자에는 열려 있는 항목만 들어 있으며, 이웃 항목의 더 큰 파일은 이미지로 미리 가져오고 동영상은 절대 미리 가져오지 않습니다. 썸네일이 흐린 상태로 즉시 나타나고, 큰 파일이 로드되면 그 위를 덮습니다. 열리는 데는 데스크톱에서 약 16 ms가 걸립니다.

더 큰 파일은 이미지의 주소 규칙(앱의 경로 또는 허용된 `https` 주소)을 따르며, 규칙을 어기면 이미지 자체의 파일을 사용합니다. 동영상 파일은 소스의 유효한 미디어 id여야 하며, 소스는 요청마다 권한을 확인하고 범위(range) 응답을 제공합니다. 대화상자는 W3C APG 대화상자 패턴을 따릅니다. 포커스가 닫기 버튼으로 이동하고, Tab과 Shift+Tab은 대화상자 안에 머물며, 닫으면 포커스가 그것을 연 이미지로 돌아갑니다(그동안 피드가 이미지를 언로드했다면 그 게시물로). 각 이미지 링크의 이름은 alt 텍스트이고, alt가 비어 있으면 "이미지 열기"입니다. 위치("4개 중 2번째")는 음성으로 안내됩니다. 모션은 `prefers-reduced-motion`을 따르며, 대화상자가 열려 있는 동안 뒤의 페이지는 스크롤되지 않습니다.

| Key | What it does |
|---|---|
| Enter | 이미지에서: lightbox를 엽니다 |
| Right, Left | 다음 항목과 이전 항목(오른쪽에서 왼쪽 쓰기에서는 반대); 확대된 이미지를 이동합니다 |
| Up, Down | 확대된 이미지를 이동합니다 |
| Home, End | 첫 항목과 마지막 항목 |
| +, -, 0 | 확대, 축소, 확대 초기화 |
| Escape | lightbox를 닫고 포커스를 돌려줍니다 |
| Tab, Shift+Tab | 대화상자를 벗어나지 않고 버튼 사이를 이동합니다 |

더블 클릭, 더블 탭, 확대 버튼으로도 확대되며, 확대된 이미지는 드래그로 이동합니다.

## Feed

`Feed`는 최신순으로 끝없이 이어지는 게시물 스트림입니다. `CardGrid`가 쓰는 것과 같은 종류의 액션으로 행을 불러옵니다(입력은 커서가 있는 `DataQuery`, 출력은 `Page`). 액션의 순서가 곧 피드의 순서이고, 배치 크기는 서버가 정하며(`.batch(n)`, 지정하지 않으면 10, 최대 `MAX_FEED_BATCH`인 50), `.scope(field, value)`는 클라이언트가 바꿀 수 없는 필터를 고정합니다. 각 행은 `Post`가 됩니다. 사진과 핸들이 있는 작성자, 시간, 본문, lightbox에서 열리는 최대 `MAX_POST_MEDIA`(4)개의 이미지, 피드의 반응과 게시물의 집계, 댓글 수, 공유 버튼으로 구성됩니다.

```rust
Feed::of(search_posts)
    .title(t!("social.feed"))
    .post(|p: &Story| Post::new(p.author.clone(), p.at)
        .avatar(p.avatar.clone())
        .text(p.text.clone())
        .media(Image::new(p.thumb.clone()).alt(p.alt.clone()).size(300, 300).full(p.photo.clone()))
        .reactions(p.reactions())
        .comments(p.comments)
        .link(story, StoryParams { id: p.id }))
    .reactions(react_to_post)
    .reaction("like", t!("social.like"), "\u{1f44d}")
    .topic("posts")
```

피드는 W3C APG의 feed 패턴을 따릅니다. `<article>` 요소로 이루어진 `role="feed"` 영역이며, 각 요소는 포커스를 받을 수 있고 작성자로 이름이 붙고 본문으로 설명되며 `aria-posinset`으로 번호가 매겨집니다(더 불러올 수 있는 동안 `aria-setsize`는 -1). 배치를 불러오는 동안 `aria-busy`가 설정됩니다. 독자가 끝에 가까워지면 이전 게시물을 불러오며, 대체 수단으로 "더 보기"가 있습니다. 모든 텍스트는 이스케이프되고 게시물의 텍스트는 줄바꿈을 유지합니다.

새 게시물은 독자가 보고 있는 내용을 절대 움직이지 않습니다. `.topic(..)`의 토픽이 새로 고쳐지면(`ui.refresh("posts")`로 끝나는 액션, 또는 `.live()`가 있는 실시간 hub) 피드는 첫 배치를 요청하고 가장 최신 게시물보다 위에 있는 게시물을 보류합니다. 피드 위의 버튼이 "새 게시물 3개"라고 표시하고 상태 영역도 같은 내용을 알립니다. 누르면 스크롤 위치를 유지한 채 위에 삽입하고 포커스를 첫 새 게시물로 옮깁니다. 한 배치가 담을 수 있는 것보다 새 게시물이 더 많이 도착하면 버튼은 피드를 가장 최신부터 다시 시작합니다.

메모리는 한계 안에 유지됩니다. 뷰포트 근처의 게시물만 페이지에 있고, 나머지는 원래 높이를 가진 HTML로 보관되며 차지하는 공간은 패딩이므로 다시 돌아와도 아무것도 튀지 않습니다. 게시물은 페이지에 있는 동안 자신의 요소를 유지하므로 포커스와 행 키가 그대로 남고, 멀리 스크롤된 포커스 게시물은 자기 자리 위에서 페이지에 남습니다. 게시물이 1,000개를 넘으면 독자보다 한참 뒤에 있는 가장 오래된 게시물은 버려지고 버튼이 가장 최신으로 돌아가는 방법을 제공합니다.

반응을 누르면 게시물의 키가 전송됩니다. 서버는 피드 자체의 액션이 피드의 scope로 그 게시물을 사용자에게 반환한 뒤에만 반응 액션을 실행하므로(해당 권한, CSRF 검사, 쓰기 속도 제한 포함) 읽을 수 없는 게시물에는 아무도 반응할 수 없습니다. 액션은 키를 `ReactionPress::target`으로 받습니다. `feed.js`(15.7 KB, gzip 5.3 KB)와 `feed.css`(3.6 KB)는 피드가 있는 페이지에서만 로드됩니다.

| Key | What it does |
|---|---|
| Tab | 게시물로 들어간 뒤 그 링크와 버튼을 차례로 이동합니다 |
| Page Down, Page Up | 포커스를 다음 또는 이전 게시물로 옮기며, 끝에서는 더 불러옵니다 |
| Control+End | 포커스를 피드 다음의 첫 요소로 옮깁니다 |
| Control+Home | 포커스를 피드 앞의 마지막 요소로 옮깁니다 |

컴포넌트 카탈로그의 소셜 데모(id에서 만든 10,000개의 게시물, 3분의 1은 사진 포함)에서 Chrome 1440 x 900으로, 10개씩 배치로 불러오며 2,000개의 게시물을 스크롤해 측정했습니다. CPU 최대 부하에서 49 fps, p95 프레임 44 ms, 문서 안에는 최대 17개의 게시물과 883개의 요소, 4.6 MB의 JavaScript 힙.
