# Представления для администрирования

Компоненты для бэк-офиса: что изменилось в записи, код и данные только для чтения, штрихкоды, уведомления, доски и календари. Каждый рисуется на сервере и загружает свою таблицу стилей и скрипт только на страницах, где он используется.

## DiffView

`DiffView` показывает поля, которые изменились между двумя значениями записи: старое значение зачёркнуто, новое отмечено как добавленное. Его строят из записи аудита через `DiffView::changes(entry.changes)` или из двух значений модели через `DiffView::of(&before, &after)`, который сравнивает их так же, как журнал аудита (версии строк не учитываются).

```rust
DiffView::of(&before, &after).title(t!("orders.history"))

DiffView::changes(entry.changes.clone())
    .model::<Order>()
    .layout(DiffLayout::Inline)
```

`.model::<M>()` даёт полям подписи на языке пользователя, а полям выбора подписи вариантов. Раскладка рядом представляет собой таблицу со столбцом старых значений и столбцом новых; `DiffLayout::Inline` ставит новое значение после старого, для узких мест вроде окна. Показывается не более `MAX_DIFF_FIELDS` (200) полей, об остальных говорит примечание.

Маскированные поля остаются маскированными. Значения берутся в том маскированном виде, в каком их хранит журнал аудита, а поле, помеченное в модели `#[mask]`, маскируется ещё раз перед показом, поэтому даже список изменений, собранный вручную, не выводит на страницу исходное значение. Скрипт компоненту не нужен; `diff.css` (1,9 КБ) загружается только вместе с ним.

## CodeView и JsonView

`CodeView` показывает исходный текст только для чтения: подсветка на сервере, номера строк, сворачивание и кнопка копирования. `JsonView` так же показывает значение JSON с отступами.

```rust
CodeView::new(CodeLang::Sql, query_text).title("report.sql")

JsonView::new(&payload).title(t!("webhooks.last_payload"))

JsonView::of(&customer, &ctx)
```

Подсветка (`zeyn::ui::highlight`) написана вручную для Rust, JSON, TOML, SQL, JavaScript и shell; `CodeLang::Plain` и любое другое имя показывают экранированный текст. Она оборачивает ключевые слова, строки, числа, комментарии, типы и ключи в span `z-hl-*`, цвета которых берутся из токенов темы, поэтому работают обе темы, а браузеру ничего не нужно делать. Блоки в скобках (`{}` и `[]`), занимающие несколько строк, сворачиваются встроенным элементом `<details>` без скрипта: первая строка служит кнопкой (Enter или Space), а свёрнутый блок заканчивается многоточием.

`JsonView::of(value, &ctx)` сериализует любое значение так же, как его отправляют в браузер конечные точки, поэтому маскированные поля остаются маскированными. Показывается не более `MAX_CODE_LINES` (10 000) строк и `MAX_CODE_BYTES` (1 МБ); более длинный текст обрезается по концу строки с примечанием о том, сколько строк показано. Кнопка копирования (`share.js`, который обслуживает и `Share`) копирует показанные строки и подтверждает это уведомлением; до запуска скрипта она скрыта. `code.css` (2,7 КБ) загружается только вместе с компонентом.

| Клавиша | Что делает |
|---|---|
| Tab | Переходит к тексту (одна остановка, прокрутка стрелками), затем по кнопкам сворачивания и кнопке копирования |
| Enter, Space | На кнопке сворачивания: сворачивает или разворачивает блок |

## Barcode и QrCode

`Barcode::code128(value)` и `QrCode::new(value)` рисуют символ в виде SVG на сервере. Оба кодировщика написаны вручную по открытым стандартам (Code 128 и QR Code), поэтому не добавляется ни crate, ни скрипт.

```rust
Row::new()
    .col(Barcode::code128(order.number.clone()).height(56))
    .col(QrCode::new(order_url).level(QrLevel::Quartile).label(t!("orders.scan")))
```

`Barcode` кодирует от 1 до 80 печатных символов ASCII (`MAX_BARCODE_CHARS`) и упаковывает серии цифр по две в символ (набор C), добавляя контрольный символ и свободную зону в 10 модулей с каждой стороны. `QrCode` кодирует текст как байты UTF-8 в наименьшей версии (от 1 до 40), которая вмещает его на выбранном уровне (`QrLevel::Low`, `Medium` по умолчанию, `Quartile`, `High`), с коррекцией ошибок Рида Соломона, маской с наименьшим штрафом и свободной зоной в 4 модуля; не более `MAX_QR_BYTES` (2953) байт. Значение, которое нельзя закодировать, показывает короткое примечание вместо испорченного символа.

Каждый символ представляет собой figure, который экранные дикторы озвучивают как одно изображение с именем из текста под ним: само значение или `.label(text)`, если оно задано. Штрихи остаются чёрными на белой подложке в обеих темах, потому что сканерам нужны тёмные штрихи на светлом фоне. `barcode.css` (1 КБ) загружается только вместе с компонентами; `.height(px)` и `.size(px)` задают размер рисунка, а в узком контейнере символ уменьшается.

## Inbox и NotificationCenter

`Inbox` показывает уведомления пользователя, новые сверху, сгруппированные по дням в часовом поясе пользователя (сегодня, вчера, затем даты), и отмечает непрочитанные. Строки приходят из действия того же вида, что и у DataGrid (на входе `DataQuery`, на выходе `Page`); список сортируется по полю времени и запрашивает не больше `.limit(n)` строк (50, максимум `MAX_INBOX`, то есть 200). `NotificationCenter` это колокольчик верхней панели: ссылка на экран входящих с числом непрочитанных.

```rust
#[action(permission = "notes.write")]
pub async fn mark_notes_read(s: InboxSelection, store: Notes, ctx: Ctx) -> Result<()> {
    store.mark_read(ctx.identity(), &s.ids)
}

#[action(permission = "notes.read")]
pub async fn count_unread(q: UnreadCount, store: Notes, ctx: Ctx) -> Result<u32> {
    store.count_unread(ctx.identity(), q.limit)
}

Inbox::of(my_notifications)
    .when(Note::created_at)
    .read(Note::read)
    .item(|n: &Note| ListItem::new(n.title.clone()).subtitle(n.body.clone()))
    .mark_read(mark_notes_read)
    .archive(archive_notes)

App::new("Admin").header(|h| h.end(NotificationCenter::of(count_unread, inbox, ())))
```

С `.mark_read(action)` и `.archive(action)` у каждой строки появляется флажок, а у списка панель с «Выбрать все». Кнопки отправляют выбранные ключи как `InboxSelection` через `POST /_zeyn/data`, который проверяет CSRF, учитывается в лимите записи и проверяет доступ к экрану и право на действие; принимается не больше 200 ключей длиной до 200 символов. Ключи приходят из браузера, поэтому действие меняет только уведомления `ctx.identity()`. Кнопки, которые пользователю недоступны, не показываются, как и флажки.

После массового действия список называет свою тему (`"notifications"`, изменить можно через `.topic(..)`): список и все узлы, которые её `.listens`, перерисовываются на месте, а колокольчик заново загружает число. Колокольчик считает действием, которое получает `UnreadCount { limit }` и останавливается на пределе (100), то есть одним ограниченным запросом; больше 99 показывается как `99+`, а имя ссылки сообщает число экранным дикторам. Число загружается одним запросом после показа страницы и снова, когда тему называет список, `ui.refresh("notifications")` или, с `.live()` и функцией `realtime`, `socket.notify(&ctx, "notifications")` в любом действии (тему нужно объявить через `ZeynSocket::topic`). `inbox.js` (6,1 КБ, 2,3 КБ в gzip) и `inbox.css` (3,1 КБ) загружаются только вместе с компонентами.

## Kanban

`Kanban::of(flow, cards, move_card)` показывает записи действия как карточки в столбцах, по одному на каждое состояние перечисления `#[choice]` рабочего процесса, в его порядке. Каждый столбец является виртуальным списком карточек в этом состоянии: действие получает `DataQuery`, ограниченный состоянием, поэтому фильтрует в базе данных, а карточки подгружаются блоками по 50 (`KANBAN_BLOCK`) по мере прокрутки столбца. В заголовке столбца показаны число карточек и предел WIP; столбец сверх предела отмечается.

```rust
#[action(permission = "tasks.work")]
pub async fn move_task(r: TransitionRequest<TaskId>, store: Tasks, ctx: Ctx) -> Result<TaskId> {
    let mut task = store.get(r.id)?;
    task.state = task_flow().apply(&ctx, task.state, &r.transition, r.comment.as_deref())?;
    store.save(task)
}

Kanban::of(task_flow(), search_tasks, move_task)
    .state(Task::state)
    .card(|t: &Task| Stack::new().add(Paragraph::new(t.title.clone())).add(Badge::new(t.owner.clone())))
    .wip(TaskState::Doing, 5)
    .confirm("reopen", t!("tasks.reopen_confirm"))
```

Перенос карточки из одного столбца в другой запускает переход между двумя состояниями с `TransitionRequest`, как это делает `Transitions`. Доска предлагает только те переносы, которые пользователь может сделать; сервер находит переход, проверяет его право и право действия переноса (CSRF и лимит записи через `POST /_zeyn/data`), а действие применяет его через `Workflow::apply`, который отклоняет карточку, если она уже в другом состоянии. `.confirm(name, message)` сначала спрашивает в общем диалоге. Карточка переносится сразу; если сервер отказывает, она возвращается в свой столбец с причиной, а если принимает, оба столбца перерисовываются одним запросом.

Мышь или перо перетаскивают карточку; допустимые столбцы обводятся, остальные тускнеют. На сенсорных экранах столбцы продолжают прокручиваться, а кнопка на каждой карточке открывает то же меню, что и клавиатура (WCAG 2.5.7). `kanban.js` (15,5 КБ, 5 КБ в gzip) и `kanban.css` (4 КБ) загружаются только вместе с доской, `vlist.js` вместе с её столбцами.

| Клавиша | Что делает |
|---|---|
| Tab | Переходит на доску, к карточке, которая была в фокусе последней (одна остановка на доску) |
| Up, Down | Предыдущая или следующая карточка в столбце |
| Left, Right | Карточка на том же месте в предыдущем или следующем столбце (меняются местами при `dir="rtl"`) |
| Home, End | Первая или последняя видимая карточка столбца |
| Enter, Space | Открывает меню переноса: Up и Down выбирают столбец, Enter переносит, Escape закрывает |
| Shift + Left, Shift + Right | Переносит карточку в предыдущий или следующий столбец, если процесс это позволяет |

## Calendar

`Calendar::of(action)` показывает события за месяц, неделю или день в часовом поясе пользователя. Действие того же вида, что у DataGrid, и получает только видимый диапазон: один фильтр оставляет события, которые начинаются не позже последнего видимого дня, другой оставляет те, что заканчиваются не раньше первого (границы дат означают целые дни в поясе пользователя, поэтому работу делает база данных), с сортировкой по началу, не больше `MAX_CALENDAR_EVENTS` (500). Сервер размещает каждое событие и рисует весь вид; время показывается в поясе `Ctx` (`TimePolicy`), поэтому событие в 23:30 UTC в Берлине относится к следующему дню.

```rust
#[action(permission = "events.write")]
pub async fn new_event(slot: CalendarSlot) -> Result<Option<Effect>> {
    Ok(Some(Window::open(event_form, EventFormParams { start: slot.start, end: slot.end })))
}

#[screen(route = "/planner", permission = "events.read")]
pub fn planner(p: CalendarParams) -> Screen {
    Screen::new(t!("planner.title")).body(
        Calendar::of(search_events)
            .start(Event::starts)
            .end(Event::ends)
            .label(|e: &Event| e.title.clone())
            .open(|e: &Event| Window::open(event, EventParams { id: e.id }))
            .create(new_event)
            .at(p),
    )
}
```

Вид и дата являются параметрами экрана (`CalendarParams` или поля с именами `view` и `date`). Ссылки панели (назад, сегодня, вперёд, месяц, неделя, день) меняют их на месте через тему календаря (`"calendar"`, `.topic(..)`): один `POST /_zeyn/nodes` перерисовывает календарь, а адрес следует за ним, поэтому видом можно поделиться, и он работает без скрипта. `.open(|e| effect)` делает каждое событие кнопкой, которая выполняет эффект, например окно, экран которого сам проверяет доступ. С `.create(action)` пользователь выбирает интервал: щелчок по дню, перетаскивание по часам или Shift со стрелками, затем Enter или N. Интервал уходит как местное время через `POST /_zeyn/data` (CSRF, лимит записи, право действия); сервер читает его в поясе пользователя, отклоняет час, пропускаемый при переводе часов, и интервалы длиннее 31 дня и передаёт действию `CalendarSlot`, чей эффект выполняется до того, как календарь перерисуется. Пользователи без права не могут выбирать интервалы. `.hours(from, to)` задаёт строки недельного и дневного вида (с 7 до 21).

Измерено в каталоге компонентов (сервер debug): переключение между месяцем, неделей и днём показывает новый вид через 21–34 мс после щелчка на полной скорости процессора и через 60–163 мс при замедлении в 4 раза. `calendar.js` (9,6 КБ, 3,3 КБ в gzip) и `calendar.css` (4,4 КБ) загружаются только вместе с календарём.

| Клавиша | Что делает |
|---|---|
| Tab | Переходит в сетку, к выбранному дню (одна остановка на сетку) |
| Стрелки | Следующий день или час; Left и Right меняются местами при `dir="rtl"` |
| Home, End | Первая или последняя ячейка строки |
| Page Up, Page Down | Предыдущий или следующий месяц, неделя или день |
| Enter | Переходит к событиям ячейки (Up и Down между ними, Escape обратно); в пустой ячейке создаёт событие |
| Shift + стрелки | Расширяет выбранный интервал, если календарь умеет создавать |
| N | Создаёт событие в выбранном интервале, если календарь умеет создавать |
