# Представления для администрирования

Компоненты для бэк-офиса: что изменилось в записи, код и данные только для чтения, штрихкоды, уведомления, доски и календари. Каждый рисуется на сервере и загружает свою таблицу стилей и скрипт только на страницах, где он используется.

## DiffView

`DiffView` показывает поля, которые изменились между двумя значениями записи: старое значение зачёркнуто, новое отмечено как добавленное. Его строят из записи аудита через `DiffView::changes(entry.changes)` или из двух значений модели через `DiffView::of(&before, &after)`, который сравнивает их так же, как журнал аудита (версии строк не учитываются).

```rust
DiffView::of(&before, &after).title(t!("orders.history"))

DiffView::changes(entry.changes.clone())
    .model::<Order>()
    .layout(DiffLayout::Inline)
```

`.model::<M>()` даёт полям подписи на языке пользователя, а полям выбора подписи вариантов. Раскладка рядом представляет собой таблицу со столбцом старых значений и столбцом новых; `DiffLayout::Inline` ставит новое значение после старого, для узких мест вроде окна. Показывается не более `MAX_DIFF_FIELDS` (200) полей, об остальных говорит примечание.

Маскированные поля остаются маскированными. Значения берутся в том маскированном виде, в каком их хранит журнал аудита, а поле, помеченное в модели `#[mask]`, маскируется ещё раз перед показом, поэтому даже список изменений, собранный вручную, не выводит на страницу исходное значение. Скрипт компоненту не нужен; `diff.css` (1,9 КБ) загружается только вместе с ним.

## CodeView и JsonView

`CodeView` показывает исходный текст только для чтения: подсветка на сервере, номера строк, сворачивание и кнопка копирования. `JsonView` так же показывает значение JSON с отступами.

```rust
CodeView::new(CodeLang::Sql, query_text).title("report.sql")

JsonView::new(&payload).title(t!("webhooks.last_payload"))

JsonView::of(&customer, &ctx)
```

Подсветка (`zeyn::ui::highlight`) написана вручную для Rust, JSON, TOML, SQL, JavaScript и shell; `CodeLang::Plain` и любое другое имя показывают экранированный текст. Она оборачивает ключевые слова, строки, числа, комментарии, типы и ключи в span `z-hl-*`, цвета которых берутся из токенов темы, поэтому работают обе темы, а браузеру ничего не нужно делать. Блоки в скобках (`{}` и `[]`), занимающие несколько строк, сворачиваются встроенным элементом `<details>` без скрипта: первая строка служит кнопкой (Enter или Space), а свёрнутый блок заканчивается многоточием.

`JsonView::of(value, &ctx)` сериализует любое значение так же, как его отправляют в браузер конечные точки, поэтому маскированные поля остаются маскированными. Показывается не более `MAX_CODE_LINES` (10 000) строк и `MAX_CODE_BYTES` (1 МБ); более длинный текст обрезается по концу строки с примечанием о том, сколько строк показано. Кнопка копирования (`share.js`, который обслуживает и `Share`) копирует показанные строки и подтверждает это уведомлением; до запуска скрипта она скрыта. `code.css` (2,7 КБ) загружается только вместе с компонентом.

| Клавиша | Что делает |
|---|---|
| Tab | Переходит к тексту (одна остановка, прокрутка стрелками), затем по кнопкам сворачивания и кнопке копирования |
| Enter, Space | На кнопке сворачивания: сворачивает или разворачивает блок |

## Barcode и QrCode

`Barcode::code128(value)` и `QrCode::new(value)` рисуют символ в виде SVG на сервере. Оба кодировщика написаны вручную по открытым стандартам (Code 128 и QR Code), поэтому не добавляется ни crate, ни скрипт.

```rust
Row::new()
    .col(Barcode::code128(order.number.clone()).height(56))
    .col(QrCode::new(order_url).level(QrLevel::Quartile).label(t!("orders.scan")))
```

`Barcode` кодирует от 1 до 80 печатных символов ASCII (`MAX_BARCODE_CHARS`) и упаковывает серии цифр по две в символ (набор C), добавляя контрольный символ и свободную зону в 10 модулей с каждой стороны. `QrCode` кодирует текст как байты UTF-8 в наименьшей версии (от 1 до 40), которая вмещает его на выбранном уровне (`QrLevel::Low`, `Medium` по умолчанию, `Quartile`, `High`), с коррекцией ошибок Рида Соломона, маской с наименьшим штрафом и свободной зоной в 4 модуля; не более `MAX_QR_BYTES` (2953) байт. Значение, которое нельзя закодировать, показывает короткое примечание вместо испорченного символа.

Каждый символ представляет собой figure, который экранные дикторы озвучивают как одно изображение с именем из текста под ним: само значение или `.label(text)`, если оно задано. Штрихи остаются чёрными на белой подложке в обеих темах, потому что сканерам нужны тёмные штрихи на светлом фоне. `barcode.css` (1 КБ) загружается только вместе с компонентами; `.height(px)` и `.size(px)` задают размер рисунка, а в узком контейнере символ уменьшается.

## Inbox и NotificationCenter

`Inbox` показывает уведомления пользователя, новые сверху, сгруппированные по дням в часовом поясе пользователя (сегодня, вчера, затем даты), и отмечает непрочитанные. Строки приходят из действия того же вида, что и у DataGrid (на входе `DataQuery`, на выходе `Page`); список сортируется по полю времени и запрашивает не больше `.limit(n)` строк (50, максимум `MAX_INBOX`, то есть 200). `NotificationCenter` это колокольчик верхней панели: ссылка на экран входящих с числом непрочитанных.

```rust
#[action(permission = "notes.write")]
pub async fn mark_notes_read(s: InboxSelection, store: Notes, ctx: Ctx) -> Result<()> {
    store.mark_read(ctx.identity(), &s.ids)
}

#[action(permission = "notes.read")]
pub async fn count_unread(q: UnreadCount, store: Notes, ctx: Ctx) -> Result<u32> {
    store.count_unread(ctx.identity(), q.limit)
}

Inbox::of(my_notifications)
    .when(Note::created_at)
    .read(Note::read)
    .item(|n: &Note| ListItem::new(n.title.clone()).subtitle(n.body.clone()))
    .mark_read(mark_notes_read)
    .archive(archive_notes)

App::new("Admin").header(|h| h.end(NotificationCenter::of(count_unread, inbox, ())))
```

С `.mark_read(action)` и `.archive(action)` у каждой строки появляется флажок, а у списка панель с «Выбрать все». Кнопки отправляют выбранные ключи как `InboxSelection` через `POST /_zeyn/data`, который проверяет CSRF, учитывается в лимите записи и проверяет доступ к экрану и право на действие; принимается не больше 200 ключей длиной до 200 символов. Ключи приходят из браузера, поэтому действие меняет только уведомления `ctx.identity()`. Кнопки, которые пользователю недоступны, не показываются, как и флажки.

После массового действия список называет свою тему (`"notifications"`, изменить можно через `.topic(..)`): список и все узлы, которые её `.listens`, перерисовываются на месте, а колокольчик заново загружает число. Колокольчик считает действием, которое получает `UnreadCount { limit }` и останавливается на пределе (100), то есть одним ограниченным запросом; больше 99 показывается как `99+`, а имя ссылки сообщает число экранным дикторам. Число загружается одним запросом после показа страницы и снова, когда тему называет список, `ui.refresh("notifications")` или, с `.live()` и функцией `realtime`, `hub.notify(&ctx, "notifications")` в любом действии (тему нужно объявить через `Realtime::topic`). `inbox.js` (6,1 КБ, 2,3 КБ в gzip) и `inbox.css` (3,1 КБ) загружаются только вместе с компонентами.
