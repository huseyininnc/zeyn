# Темы оформления

Статус: реализовано в `crates/zeyn/assets/zeyn.css`.

Стандартный набор UI берёт каждый цвет, шрифт, размер и радиус из CSS custom properties в `:root`. Организация меняет внешний вид, переопределяя несколько из них. Править `zeyn.css` или писать селекторы не нужно.

## 1. Как применяется тема

Сервер сначала отдаёт `zeyn.css`, а затем, если у приложения он есть, дополнительную таблицу стилей с переопределениями токенов. Файл переопределений содержит только блоки `:root`:

```css
:root {
  --z-brand: #7a2448;
  --z-font: "Source Sans 3", "Segoe UI", system-ui, sans-serif;
  --z-radius: 8px;
  --z-density: 0.75;
}
```

Правила для файла переопределений:

- Он должен отдаваться с собственного origin приложения. Content Security Policy задана как `style-src 'self'`, поэтому встроенные блоки `<style>` и сторонние таблицы стилей блокируются.
- Шрифты должны быть уже установлены на машинах пользователей или отдаваться с origin приложения. Сам набор не загружает веб-шрифты.
- Подключайте файл после `zeyn.css`, чтобы при равных селекторах побеждал порядок.
- Задавайте базовые токены из раздела 2. Производные токены из раздела 3 следуют за ними автоматически. Переопределяйте производный токен только тогда, когда вычисленное значение не подходит вашему бренду.

### Светлая, тёмная и тематики приложения

В каждом приложении в меню, рядом с выбором языка, есть выбор темы. Он предлагает System (следует `prefers-color-scheme`), Light, Dark и любые темы, которые определило приложение:

```rust
App::new("Billing")
    .theme(Theme::new().brand("#7a2448").radius(6))
    .themes([
        Theme::light(),
        Theme::dark(),
        Theme::named("sand", [("--z-bg", "#f5f1ea"), ("--z-surface", "#fffdf8")]).label(t!("theme.sand")),
    ])
    .default_theme("system")
```

- `App::theme` задаёт внешний вид организации и действует во всех темах.
- `App::themes` перечисляет то, что могут выбрать пользователи. Без неё список состоит из Light и Dark. System предлагается, когда в списке есть обе. `Theme::named(...)` строится на светлой теме; `.dark_base()` строит её на тёмной.
- `App::default_theme` задаёт тему для пользователей, которые ничего не выбрали. Если не задана, используется `system`.
- `App::theme_picker(false)` скрывает выбор темы; все получают тему по умолчанию.
- Одна тема фиксирует приложение: `.themes([Theme::named("acme", tokens)])` или `.theme(Theme::dark())`.

Токены проверяются при запуске приложения. `App::check` (а значит, `router` и `serve`) сообщает об неизвестных именах токенов, о значениях, которые могут выйти за пределы своего объявления (`;`, фигурные скобки, `\`, `<`, `>`, `url(`), о некорректных именах тем, об неизвестной теме по умолчанию и о каждой цветовой паре из раздела 5, которую тема опускает ниже WCAG 2.2 AA. Контраст можно проверить только для значений `#rgb` и `#rrggbb`; другой синтаксис цвета принимается на доверии.

Все темы отдаются одной таблицей стилей, `/_zeyn/theme.css`, которая строится один раз при запуске и подключается после стилей набора. Выбор хранится в cookie `zeyn_theme` и, для вошедшего пользователя в приложении с хранилищем представлений (`App::datagrid_views`), в этом хранилище, поэтому он следует за пользователем на новое устройство. Сервер выводит тему в `<html>`, поэтому первая отрисовка уже верна и встроенный скрипт не нужен:

| Разметка | Результат |
|---|---|
| `<html>` | System: следует `prefers-color-scheme` |
| `<html data-theme="light">` | Всегда светлая |
| `<html data-theme="dark">` | Всегда тёмная |
| `<html data-theme="light" data-zeyn-theme="sand">` | Тема приложения `sand` на основе светлой |

Смена темы в выборе меняет только эти атрибуты и meta `color-scheme`, а затем вызывает `POST /_zeyn/theme`. Ничего не перезагружается.

Чтобы задать тёмной теме собственные значения в файле переопределений, написанном вручную, повторите селекторы, которые использует набор:

```css
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { --z-bg: #0e1012; }
}
:root[data-theme="dark"] { --z-bg: #0e1012; }
```

### Плотность

`--z-density` масштабирует единицу отступа. `1` соответствует обычной плотности, `0.75` компактной. `<html data-density="compact">` задаёт `0.75` без таблицы стилей. Элементы управления и строки сетки никогда не становятся меньше 24 px, поэтому компактный режим по-прежнему соответствует размеру цели WCAG 2.2.

Высота строки виртуальной сетки задаётся сервером (`Paging::virtual_rows(px)`, по умолчанию 32 px), потому что рантайм вычисляет по ней позиции прокрутки. Плотность её не меняет.

## 3. Производные токены

Вычисляются из базовых токенов с помощью `color-mix()` и синтаксиса относительных цветов. Обновляются сами при изменении базового токена.

| Токен | Назначение | Светлая | Тёмная |
|---|---|---|---|
| `--z-accent` | Цвет бренда, используемый как текст или тонкая линия на поверхности: ссылки, текущий пункт меню, полоса строки в фокусе | `var(--z-brand)` | `oklch(from var(--z-brand) 0.8 c h)`, оттенок бренда с фиксированной светлотой. Браузеры без синтаксиса относительных цветов получают `color-mix(in oklab, var(--z-brand) 45%, #fff)` |
| `--z-primary` | Заливка основной кнопки | `var(--z-brand)` | `var(--z-accent)` |
| `--z-on-primary` | Текст основной кнопки | `var(--z-on-brand)` | `#121416` |
| `--z-primary-hover` | Основная кнопка при наведении | бренд 86% с примесью чёрного | акцент 84% с примесью белого |
| `--z-primary-active` | Основная кнопка в нажатом состоянии | бренд 74% с примесью чёрного | акцент 70% с примесью белого |
| `--z-brand-subtle` | Оттенок под текущим пунктом меню и строкой сетки в фокусе | акцент при `--z-tint` поверх `--z-surface` | та же формула |
| `--z-focus` | Кольцо фокуса | `var(--z-accent)` | `var(--z-accent)` |
| `--z-danger-subtle`, `--z-warning-subtle`, `--z-success-subtle`, `--z-info-subtle` | Фоны строк и сообщений | цвет статуса при `--z-tint` поверх `--z-surface` | та же формула |
| `--z-tint` | Сила приглушённых оттенков | `9%` | `20%` |
| `--z-space` | Единица отступа | `calc(4px * var(--z-density))` | то же |
| `--z-control` | Высота кнопки и поля ввода | `max(24px, 8 * --z-space)` (32 px) | то же |
| `--z-row` | Высота строки сетки для постраничных и бесконечных сеток | `max(24px, 8 * --z-space)` (32 px) | то же |
| `--z-gap` | Промежуток между секциями экрана | `3 * --z-space` (12 px) | то же |
| `--z-radius-sm`, `--z-radius-lg` | Мелкие части (фильтры, код), окна | `0.75x` и `1.5x` от `--z-radius` | то же |
| `--z-shadow-2` | Только окна и уведомления. У строк сетки тени нет | мягкая двухслойная тень | темнее |
| `--z-backdrop` | Фон за модальным окном | `rgb(20 24 28 / 40%)` | `rgb(0 0 0 / 60%)` |
| `--z-dir` | Направление чтения в виде знака, для смещений без логической формы (внутренние тени, отмечающие начальную или конечную сторону, сдвиги): `calc(2px * var(--z-dir))` | `1`, и `-1` при `dir="rtl"` | то же |

Токены отдельных элементов, которые задаёт серверная разметка: `--z-width` (ширина окна), `--z-flex` (доля столбца), `--z-row-height` (высота строки виртуальной сетки), а для библиотеки компонентов `--z-stack-gap`, `--z-split`, `--z-progress`, `--z-columns`, `--z-level` и `--z-pop-x` / `--z-pop-y` (позиция всплывающего окна).

Цвета рядов диаграмм это `--z-chart-1` ... `--z-chart-6` в `components.css`, в тёмной теме с более светлыми значениями. Каждый достигает 3:1 относительно `--z-surface`. Переопределяйте их как любой базовый токен.

## 4. Выбор цвета бренда

- `--z-brand` несёт белый текст в светлой теме (кнопки, полоса с названием приложения). Выбирайте цвет с контрастом не менее 4.5:1 относительно `--z-on-brand`. Большинство средних и тёмных цветов бренда проходят. Для светлого цвета бренда, например жёлтого, задайте также тёмный `--z-on-brand`.
- В тёмной теме набор осветляет бренд для текста, колец и основных кнопок, а сплошной бренд оставляет для полосы с названием приложения. Другой бренд выглядит продуманно в обеих темах без второго цвета.
- Держите цвета статусов отличимыми от бренда. Красный бренд рядом с красными строками ошибок затрудняет их заметность; в этом случае сдвиньте `--z-danger` к другому оттенку красного или уберите бренд из сеток, переопределив `--z-brand-subtle`.
- Проверяйте свои цвета, ориентируясь на таблицу из раздела 5. Любая пара ниже порога не проходит WCAG 2.2 AA.

## 6. Прочее поведение для доступности

- Каждый интерактивный элемент показывает кольцо `:focus-visible` толщиной 2 px цвета `--z-focus`. Строки сетки рисуют кольцо внутри строки, поэтому контейнер прокрутки его никогда не обрезает.
- Кнопки, поля ввода, заголовки сортировки, поля фильтров, кнопки пейджера и кнопка закрытия окна имеют размер не менее 24 x 24 px при любой плотности.
- `prefers-reduced-motion: reduce` убирает появление уведомлений и все переходы.
- В режиме `forced-colors` значки используют `CanvasText`, основная кнопка и строка в фокусе используют `Highlight`, а состояния, опирающиеся на фоновые оттенки (текущий пункт меню, статус строки), получают контур или рамку.
