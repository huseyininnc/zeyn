# CLI и проекты

Команда `zeyn` создаёт проекты, добавляет функции (features), проверяет приложение и запускает MCP-сервер для агентов.

## Команды

| Команда | Что делает |
|---|---|
| `zeyn new <name>` | Создаёт приложение со стандартной структурой функций |
| `zeyn new <name> --lib` | Создаёт библиотеку моделей, функций и текстов, общую для нескольких приложений |
| `zeyn g feature <name>` | Добавляет `src/features/<name>` с папками `models`, `services`, `actions` и `screens` и рабочим экраном списка |
| `zeyn g screen <feature> <name>` | Добавляет в фичу `screens/<name>.rs`, регистрирует его и добавляет заголовок во все файлы локалей |
| `zeyn routes` | Выводит список функций, экранов, маршрутов, API и прав доступа |
| `zeyn check` | Компилирует и сообщает о структурных проблемах и отсутствующих переводах |
| `zeyn check --fix` | Переписывает переименованные API Zeyn в `src`, `tests` и `examples`, затем проверяет |
| `zeyn mcp` | Запускает MCP-сервер через stdio для ИИ-агентов |

Установите её из crates.io:

```sh
cargo install zeyn-cli
zeyn new my-app
cd my-app
cargo run
```

Внутри этого репозитория запускайте CLI через Cargo:

```sh
cargo run -p zeyn-cli -- new my-app
cd my-app
cargo run
```

## Новое приложение

`zeyn new` создаёт проект, который собирается, проходит свои тесты и следует правилам, заданным для агентов:

- `AGENTS.md` и `CLAUDE.md`: правила проекта и указатель по фреймворку для агентов.
- `.mcp.json`: регистрирует MCP-сервер `zeyn`, чтобы агент мог вызывать `zeyn_check` и `zeyn_docs`.
- `config/app.json`: значения по умолчанию. Переменные окружения `APP_*` переопределяют их, например `APP_SERVER__ADDR` для `server.addr`.
- `locales/en.json` и `locales/tr.json`: все тексты, которые видит пользователь.
- `src/features/`: по одной папке на функцию, с примером функции `notes`.
- `rustfmt.toml`, `clippy.toml`, `deny.toml`, `rust-toolchain.toml` и `[lints]` в `Cargo.toml`: стандарты, которые обеспечивает CI.
  `rustfmt.toml` задаёт `chain_width = 40`, поэтому код читается сверху вниз: цепочка вызовов длиннее этого
  значения получает по одному вызову на строку, в среднем одна-две точки на строку. Агенты и люди
  просматривают список быстрее, чем одну длинную строку, а в диффах виден тот единственный вызов, который изменился. Сохраняйте эту настройку.

  ```rust
  DataGrid::of(search_items)
      .paging(Paging::pages(25))
      .column(Item::code)
      .column(Item::qty)
  ```

  а не `DataGrid::of(search_items).paging(Paging::pages(25)).column(Item::code).column(Item::qty)`.
- `Dockerfile` и `.dockerignore`: небольшой образ контейнера.
- Конвейеры для распространённых CI-серверов, все выполняют одни и те же проверки (`cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`, `cargo deny check`) и отклоняют тег `vX.Y.Z`, не совпадающий с `Cargo.toml`:
  - `.github/workflows/ci.yml` для GitHub Actions, с `.github/dependabot.yml` (еженедельные обновления Cargo и actions) и чек-листом для pull request;
  - `.gitlab-ci.yml` для GitLab;
  - `Jenkinsfile` для Jenkins (агент Docker, покрытие через `cargo llvm-cov`).
- `sonar-project.properties`: анализ SonarQube (замечания Clippy и покрытие LCOV из `target/lcov.info`). Рабочий процесс GitHub запускает его, когда заданы переменная репозитория `SONAR_HOST_URL` и секрет `SONAR_TOKEN`; Jenkins запускает его, когда задание устанавливает `SONAR_ENABLED=true`.
- `SECURITY.md` и `CHANGELOG.md` (Keep a Changelog).
- Локальный git-репозиторий на ветке `main`, если git установлен (Windows, macOS или Linux) и папка ещё не находится внутри репозитория. Ничего не коммитится, поэтому первый коммит несёт ваше собственное имя и адрес e-mail. `--no-git` пропускает этот шаг.

Каждая папка описана в разделе [Структура проекта](structure.md).

## Генераторы

`zeyn g feature` создаёт фичу с одним файлом на каждую модель, сервис, действие и экран:

```sh
zeyn g feature orders            # src/features/orders/: models/, services/, actions/, screens/
zeyn g screen orders detail      # src/features/orders/screens/detail.rs
```

Короткие формы `zeyn g f` и `zeyn g s` делают то же самое. Новая фича сразу работает: модель, сервис данных в памяти, действие поиска и экран списка с пунктом меню. Фича, которой папка не нужна, удаляет её (папку и её строку `mod` в `mod.rs` фичи). `components/` никогда не генерируется: добавьте её вручную, по одной функции, возвращающей `Node`, на файл (`components/<name>.rs`), когда часть экрана используется в нескольких местах или файл экрана разрастается. Экран получает разрешение `<feature>.<name>.view` и заголовок в каждом файле в `locales/`; языки кроме английского получают английский текст и напоминание перевести его. Структура не обязательна: если у фичи один файл `screens.rs`, `zeyn g screen` сначала переносит его вместе с содержимым в `screens/mod.rs`, а если папку `screens/` удалили, создаёт её заново. Генераторы никогда не перезаписывают файлы и отклоняют имена не в snake case.

## Проверка приложения

`zeyn check` запускает компилятор, а затем собственные проверки приложения (`App::check`): дублирующиеся маршруты, дважды зарегистрированные экраны, сервисы, которые нужны экрану, но никем не зарегистрированы, непригодные горячие клавиши, токены темы с контрастом ниже WCAG AA и ключи перевода, отсутствующие в каком-либо языке. При любой ошибке команда завершается с ошибкой, поэтому её может запускать CI.

Ещё она выводит предупреждения, которые никогда не проваливают проверку: `#[screen]` или `#[action]`, которые не регистрирует ни одна фича, и один файл `screens.rs` или `actions.rs` с несколькими элементами длиннее примерно 150 строк.

Когда релиз Zeyn переименовывает API, `zeyn check --fix` переписывает старые имена, например `Grid` в `DataGrid` и `GridQuery` в `DataQuery`, затем проверяет снова.

```sh
zeyn check --fix
```

## Docker

Сгенерированный `Dockerfile` собирается в два этапа и работает на образе distroless от имени пользователя без прав root. Бинарный файл проверяет собственное состояние командой `<app> health`, которую использует `HEALTHCHECK`.

```sh
docker build -t my-app .
docker run -p 3000:3000 -e APP_SERVER__ADDR=0.0.0.0:3000 my-app
```

Образ сгенерированного приложения занимает около 43 МБ, а простаивающее приложение использует несколько МБ оперативной памяти.

## MCP-сервер

`zeyn mcp` говорит по MCP через stdio. Его инструменты: `zeyn_docs` (справочник по фреймворку по темам), `zeyn_describe` (функции, экраны, маршруты и проблемы приложения в текущем каталоге), `zeyn_check` (с `fix: true` запускает `check --fix`), `zeyn_test` и `zeyn_new_feature`. См. [MCP и ИИ-агенты](mcp.md).
