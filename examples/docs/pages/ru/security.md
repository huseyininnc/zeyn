# Безопасность

Безопасность в Zeyn объявляется рядом с кодом, который она защищает, и проверяется на сервере при каждом вызове. Значения по умолчанию строгие; ослабление любого из них заметно как отдельная строка в `app.rs`.

## Разрешения

Каждое действие (action) и каждый экран (Screen) объявляют `permission = "feature.resource.verb"` или `public`. Без этого код не компилируется. Идентичность запроса несёт его разрешения:

```rust
Identity::user("ada").with_permissions(["stock.product.read", "stock.product.write"])
```

Пункты меню, кнопки панели инструментов, действия строк и команды, которые пользователю нельзя выполнять, не попадают в HTML. Это лишь удобство; сервер проверяет разрешение заново при каждом вызове.

## Вход в систему

Приложение не хранит пароли. `Authenticator` определяет, кто выполняет вызов, обычно по прокси единого входа (single sign on) перед приложением:

```rust
App::new(t!("app.name")).auth(
    ForwardAuth::new("x-forwarded-user")
        .groups("x-forwarded-groups")
        .require_header("x-proxy-secret", secret.expose())
        .role("stock-admins", ["stock.product.read", "stock.product.write"]),
)
```

Используйте `ForwardAuth` только тогда, когда каждый запрос проходит через прокси: любой, кто может обратиться к приложению напрямую, способен отправить эти заголовки. `require_header` проверяет общий секрет, который добавляет прокси. `DevAuth::superuser(name)` даёт каждому запросу полный доступ для локальной разработки, и сервер выводит предупреждение, пока он включён. Релизная сборка отказывается запускаться с ним (`App::check` сообщает об этом); демонстрация, которая должна работать в релизе, может вызвать `App::allow_dev_auth()`. Приложения, созданные через `zeyn new`, включают его только в отладочных сборках.

## Охранники (Guards)

Охранник выполняется до открытия любого экрана Feature и до вызова любой из его таблиц, форм или команд:

```rust
fn warehouse_open(ctx: &Ctx) -> GuardResult {
    if ctx.identity().permissions.contains("stock.warehouse.read") { GuardResult::Allow } else { GuardResult::Deny(t!("stock.closed")) }
}

Feature::new("stock").guard(SignedIn).guard(warehouse_open)
```

Встроенные guard-ы: `SignedIn`, `TenantRequired` и `Licensed`.

## Перехватчики (Interceptors)

Перехватчик выполняется вокруг каждого вызова экрана, таблицы, формы, API и команды после проверок доступа. `before` может остановить вызов; `after` видит, чем он закончился. `AuditLog(sink)` встроенный перехватчик, который записывает, кто что сделал.

## CSRF, CSP и заголовки

- Каждая страница устанавливает случайную cookie `zeyn_csrf` (`HttpOnly`, `SameSite=Strict`) и помещает тот же токен в meta-тег. Каждый вызов из среды выполнения отправляет его в заголовке `x-zeyn-csrf`, а сервер сравнивает оба значения за постоянное время.
- Исключение составляют публичные экраны, открытые без сессии: они не устанавливают cookie и не несут токена, поэтому их можно кэшировать. Среда выполнения получает токен через `GET /_zeyn/csrf` перед первым вызовом, и каждый `POST` по-прежнему проверяется так же (см. [Публичные страницы](public-pages.md)).
- Content Security Policy разрешает скрипты, стили и изображения только с собственного источника (origin) приложения. Встроенных скриптов нет; темы являются таблицами стилей, а не встроенными стилями.
- `App::csp` открывает политику для указанных хостов, по одной директиве за раз. Заголовок строится один раз при запуске.

```rust
App::new("Shop").csp(|c| {
    c.img_src(["https://images.example.com"])
        .frame_src(["https://www.youtube-nocookie.com", "https://*.vimeo.com"])
        .media_src(["https://media.example.com:8443"])
        .media_blob()
        .connect_src(["https://api.example.com"])
        .font_src(["https://fonts.example.com"])
})
```

  Принимаются только `https://host`, `https://host:port` и `https://*.host` (подстановочный знак соответствует поддоменам, но не самому хосту). `.media_blob()` добавляет `blob:` в `media-src` для библиотек потоковой передачи. `App::check` отклоняет `*`, `http:`, голые схемы вроде `data:` или `https:`, ключевые слова в кавычках вроде `'unsafe-inline'` или `'unsafe-eval'`, пути, имена пользователей и значения с пробелами, запятыми или точками с запятой; каждое сообщение об ошибке подсказывает, что написать вместо этого. Директивы `script-src`, `object-src`, `base-uri` и `frame-ancestors` изменить нельзя. `Embed` и `Image` читают те же списки, поэтому хост, который браузер заблокировал бы, никогда не отображается (см. [Отображение](display.md)).
- Ответы содержат `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin` и `X-Frame-Options: DENY`.
- `App::secure_cookies(true)` помечает cookie как `Secure`; включайте это за HTTPS.

## Экранирование

Пользовательские данные в HTML всегда проходят через `render::escape`. Компоненты экранируют каждое отображаемое значение, поэтому товар с названием `<script>` показывается как текст.

## Лимиты

```rust
App::new(t!("app.name"))
    .rate_limit(RateLimit::per_ip(600, Duration::from_secs(60)))
    .write_limit(RateLimit::per_user(60, Duration::from_secs(60)))
    .trusted_proxies(["10.0.0.0/8"])
    .allow_only_ips(["10.0.0.0/8", "192.168.0.0/16"])
    .deny_ips(["203.0.113.7"])
```

- `rate_limit` применяется к каждому запросу, кроме статических ресурсов и чтения публичных медиаисточников (`Feature::public_media`); `write_limit` добавляет более строгий лимит для вызовов, изменяющих данные: отправка форм, правка в таблицах, действия над строками, массовые действия и действия меню, команды, импорт, сохранённые представления таблиц, раскладки док-панелей и темы, вызовы API, вызовы MCP и ассистент. Отклонённые запросы получают `429` с `Retry-After`.
- `X-Forwarded-For` принимается на веру только от `trusted_proxies`. Учитывается каждая строка заголовка по порядку, а берётся последний адрес, не являющийся доверенным прокси.
- Раскрытия значений, вызовы островов (island) и источников данных тоже считаются записью, как и экспорт и печатные документы (`GET /_zeyn/grid/export`, `GET /_zeyn/pdf`).
- Размеры страниц, число строк, длина запросов и размеры загрузок ограничиваются на сервере независимо от того, что отправляет клиент.

## Сессии

`App::idle_timeout(d)` завершает сеанс пользователя на странице после периода без ввода, предварительно показав диалог с предупреждением. Действия с пометкой `reauth` требуют недавнего входа (`App::reauth_within`).

## Клиентские настройки

Некоторые небольшие выборы относятся к браузеру, а не к серверу: подтверждённое пользователем уведомление перед загрузкой встроенного содержимого, последняя открытая вкладка. Zeyn хранит их в одном месте, `zeyn.state` (`/_zeyn/state.js`, загружается только на страницах, которые его используют), а сервер их никогда не читает, поэтому кэшированные публичные страницы остаются одинаковыми для всех. Настройки, меняющие HTML, такие как тема и язык, остаются в cookie.

Ключ объявляется один раз как константа с видом, сроком жизни и назначением, регистрируется в приложении и привязывается к компонентам через `.remember(KEY)`: `Embed::remember` принимает ключ согласия, `Tabs::remember` ключ выбора. Простая строка или ключ другого вида не компилируется, а имя вне 1 до 40 ASCII-букв, цифр, `-` и `_` или срок жизни вне диапазона от одной секунды до 400 дней (`MAX_PREF_LIFETIME`) приводит к ошибке при создании константы. Компонент, привязанный к ключу, который приложение не зарегистрировало, не запоминается, поэтому список конфиденциальности всегда полон.

```rust
pub const VIDEO_NOTICE: ClientPref<Consent> =
    ClientPref::consent("video-notice", Duration::from_secs(86_400), Purpose::Necessary);
pub const ORDER_TAB: ClientPref<Choice> =
    ClientPref::choice("order-tab", Duration::from_secs(30 * 86_400), Purpose::Preference);

App::new(t!("app.name")).client_prefs(|p| {
    p.key(VIDEO_NOTICE)
        .key(ORDER_TAB)
        .allowed_when(|headers| consent_cookie(headers) == Some("all"))
})
```

- **Записи.** Каждое значение это `{v, exp, val}` под `zeyn.v1.{key}`. Каждое чтение проверяет версию, значение (`true` или текст не длиннее 200 символов) и время окончания, которое не должно пройти и не должно лежать дальше срока жизни ключа. Запись, не прошедшая проверку, например изменённая вручную, удаляется. Новая версия формата игнорирует старые записи.
- **Назначение.** `Purpose::Necessary` предназначено для того, о чём попросил пользователь, например подтверждение уведомления перед загрузкой содержимого с другого сайта; оно хранится в течение своего срока жизни. `Purpose::Preference` это выбор интерфейса. Директива ePrivacy (статья 5(3)) разрешает хранить данные в браузере без согласия, только когда это строго необходимо для услуги, которую запросил пользователь, а органы по защите данных ЕС (Рабочая группа по статье 29, мнение 04/2012) считают выбор интерфейса необходимым только на время сессии или несколько часов. Поэтому значения предпочтений попадают в `sessionStorage`, пока хук приложения `allowed_when(|headers| ...)` не сообщит, что пользователь согласился; браузер спрашивает `GET /_zeyn/prefs` один раз на страницу, ответ никогда не кэшируется, а без хука ответ отрицательный.
- **Вкладки и заблокированное хранилище.** Другие вкладки следуют за изменениями через событие `storage`. Когда хранилище заблокировано (приватные окна, строгие настройки), значения живут в памяти страницы. Без JavaScript компоненты показывают состояние по умолчанию.
- **Открытость.** `App::client_prefs_table()` перечисляет каждый ключ с его видом, назначением и сроком жизни в секундах для страницы конфиденциальности, а `ClearPrefs` (или `zeyn.prefs.clear()`) удаляет их все из браузера.

## API и агенты

Вызовы API требуют заголовка `Authorization`; одной cookie браузерной сессии никогда не хватает для вызова API или конечной точки MCP, поэтому CSRF-токен им не нужен. Агенты получают ровно те разрешения, что и пользователь, от имени которого они действуют. См. [API и OpenAPI](api.md) и [MCP и ИИ-агенты](mcp.md).
