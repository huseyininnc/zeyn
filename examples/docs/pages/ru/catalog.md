# Карточки, ленты и поиск

Публичные страницы, например магазин, показывают строки как карточки, а не как таблицу. `CardGrid`, `Rail` и `SearchBox` загружают свои строки через такое же действие (action), как у DataGrid: оно принимает `DataQuery` и возвращает `Page`. Разбиение на страницы, сортировка и текст поиска выполняются на сервере, а для чтения нужен доступ к действию, как и для DataGrid.

```rust
#[action(public)]
pub async fn catalog_products(q: DataQuery, store: ProductStore) -> Result<Page<Product>> {
    Ok(q.apply(store.all()?.into_iter().filter(|p| p.active).collect()))
}
```

## Сетка карточек

```rust
CardGrid::of(catalog_products)
    .title(t!("shop.products"))
    .card(|p: &Product| {
        Card::image(p.image.clone(), p.name.clone())
            .text(p.price.to_string())
            .badge(Badge::new(t!("shop.new")).tone(Tone::Success))
            .link(shop_product, ProductPage { id: p.id })
    })
    .sort_option(t!("shop.sort.name"), Product::name, false)
    .sort_option(t!("shop.sort.cheapest"), Product::price, false)
    .image_size(300, 300)
    .paging(Paging::infinite(24))
```

- **Карточки.** `Card::image(image, title)` делает одну карточку из строки, с `text`, `badge`, `alt` и `link` (экран и его параметры; вся карточка это одна ссылка и открывается без перезагрузки страницы). Изображения ленивые, с шириной и высотой из `image_size`, чтобы страница не прыгала. Альтернативный текст изображения пуст, потому что заголовок рядом называет карточку; задавайте `alt`, когда картинка говорит больше. Адреса изображений, кроме пути, `https:` или `data:image/`, отбрасываются.
- **Больше на карточке.** `subtitle` добавляет под заголовком вторую, более приглушённую строку (автор, категория). `corner(badge)` ставит бейдж на конечный угол изображения, рядом с `badge` на начальном; `badges([...])` добавляет под текстом ряд бейджей, например теги. `progress(fraction, label)` рисует тонкую полосу вдоль нижнего края изображения, показывающую, сколько сделано: доля идёт от 0 до 1, а программы чтения с экрана слышат подпись и процент (`role="progressbar"` с `aria-valuenow`). `horizontal()` раскладывает карточку в строку: маленькое изображение в начале и текст рядом с ним; сетка карточек или лента (rail) с такими карточками даёт им более широкие столбцы. Всё это работает в `CardGrid` и в `Rail`.

```rust
Card::image(c.cover.clone(), c.title.clone())
    .subtitle(c.teacher.clone())
    .corner(Badge::new(t!("courses.new")).tone(Tone::Success))
    .badges(c.tags.iter().map(|t| Badge::new(t.clone())))
    .progress(c.done, t!("courses.done"))
    .horizontal()
```
- **Разбиение на страницы.** `Paging::infinite(n)` (по умолчанию, 24) показывает кнопку "Show more", которая также срабатывает, когда прокрутка доходит до неё; при нажатии кнопки фокус переходит на первую новую карточку. `Paging::pages(n)` показывает кнопки назад и вперёд и номер страницы. Размер страницы задаёт сервер; клиент лишь говорит, откуда продолжать.
- **Сортировка.** Каждый `sort_option` это порядок, который пользователи выбирают в списке select; первый это порядок, в котором карточки показываются сначала. Сервер принимает только эти порядки и отбрасывает фильтры и текст поиска, присланные клиентом.
- **Поиск.** `.search(text)` показывает только строки, подходящие под свободный текст ([`DataQuery::q`](#free-text)), например текст с экрана результатов.
- **Маскированные поля.** Карточки строятся замыканием, которое видит исходную строку. Для модели с полями `#[mask]` карточки получают только пользователи, которым разрешено их раскрывать; все остальные получают `Forbidden`. Для публичных карточек используйте модель без маскированных полей.

## Rail

Rail это сетка карточек в одну строку, которая прокручивается вбок, с привязкой прокрутки и кнопками назад и вперёд, прокручивающими на ширину области просмотра (плавно, если только пользователь не просил уменьшить анимацию). Следующую порцию, по 12 штук, он загружает, когда пользователь прокручивает близко к концу. Карточки это ссылки в порядке обхода по Tab, и они прокручиваются в область видимости, когда получают фокус.

```rust
Rail::of(catalog_products)
    .title(t!("shop.new_arrivals"))
    .card(|p: &Product| Card::image(p.image.clone(), p.name.clone()))
    .sort_option(t!("shop.sort.newest"), Product::id, true)
```

## Поле поиска

Поле поиска с подсказками по шаблону W3C APG combobox со всплывающим списком (list box). По мере ввода оно ждёт `instant` миллисекунд и запрашивает у сервера подсказки: действие запускается с текстом в `DataQuery::q`, и возвращается текст подсказки для каждой строки (её первое немаскированное текстовое поле, если `suggestion` не говорит иначе). Enter или выбор подсказки открывает экран результатов с этим текстом, без перезагрузки страницы.

```rust
#[screen(route = "/shop/search", public)]
pub fn shop_search(p: SearchParams) -> Screen {
    Screen::new(t!("shop.search.all"))
        .body(SearchBox::of(catalog_products).value(p.q.clone()).results(shop_search))
        .body(CardGrid::of(catalog_products).card(product_card).search(p.q).paging(Paging::pages(12)))
}

SearchBox::of(catalog_products)
    .label(t!("shop.search.label"))
    .instant(150)
    .suggestion(|p: &Product| p.name.clone())
    .results(shop_search)
```

Клавиатура: стрелки вниз и вверх перемещают по подсказкам (стрелка вниз открывает их), Enter ищет по выделенной подсказке или по набранному тексту, Escape закрывает подсказки, а затем очищает поле. Живая область (live region) сообщает программам чтения с экрана, сколько подсказок.

Экран результатов принимает `SearchParams` (`q`, пусто, если экран открыт из меню). Сервер обрезает текст до `MAX_SEARCH_QUERY` (100) символов, решает, сколько подсказок отправить (8, если `limit` не говорит иначе, не более 20), проверяет доступ к экрану, защитные проверки (guards) feature и разрешение действия и учитывает каждый вызов подсказок в ограничении частоты записи (`App::write_limit`).

## Свободный текст

`DataQuery::q` это свободный текст: строки, текстовые поля которых его содержат, без учёта регистра. Турецкие `i` с точкой и без точки (`İ`, `ı`) совпадают с `i`, поэтому "istanbul" находит "İSTANBUL". Поля с `#[mask]` никогда не участвуют в поиске, пустой текст совпадает со всеми строками, а текст длиннее 100 символов игнорируется. `DataQuery::apply` и слои данных SQL (`LOWER(TRANSLATE(column, 'İı', 'ii')) LIKE ...` со связанными параметрами) читают его одинаково.
