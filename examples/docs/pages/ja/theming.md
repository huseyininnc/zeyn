# テーマ

ステータス: `crates/zeyn/assets/zeyn.css` に実装済みです。

標準の UI キットは、すべての色、フォント、サイズ、角丸を `:root` の CSS カスタムプロパティから読み取ります。組織はそのうちいくつかを上書きするだけで見た目を変更できます。`zeyn.css` を編集したり、セレクターを書いたりする必要はありません。

## 1. テーマの適用方法

サーバーはまず `zeyn.css` を配信し、アプリにトークン上書き用の追加スタイルシートがあれば、その後に配信します。上書きファイルには `:root` ブロックだけを書きます。

```css
:root {
  --z-brand: #7a2448;
  --z-font: "Source Sans 3", "Segoe UI", system-ui, sans-serif;
  --z-radius: 8px;
  --z-density: 0.75;
}
```

上書きファイルのルールは次のとおりです。

- アプリ自身のオリジンから配信する必要があります。Content Security Policy は `style-src 'self'` のため、インラインの `<style>` ブロックとサードパーティのスタイルシートはブロックされます。
- フォントは、ユーザーのマシンにインストール済みであるか、アプリのオリジンから配信されている必要があります。キット自体は Web フォントを読み込みません。
- `zeyn.css` の後に読み込みます。同じ詳細度のセレクターでは、後に書かれたものが優先されるためです。
- 設定するのはセクション 2 の基本トークンです。セクション 3 の派生トークンは自動的に追従します。計算された値がブランドに合わない場合にだけ、派生トークンを上書きしてください。

### ライト、ダーク、アプリテーマ

すべてのアプリのメニューには、言語ピッカーの隣にテーマピッカーがあります。System (`prefers-color-scheme` に従う)、Light、Dark、およびアプリが定義した任意のテーマを選べます。

```rust
App::new("Billing")
    .theme(Theme::new().brand("#7a2448").radius(6))
    .themes([
        Theme::light(),
        Theme::dark(),
        Theme::named("sand", [("--z-bg", "#f5f1ea"), ("--z-surface", "#fffdf8")]).label(t!("theme.sand")),
    ])
    .default_theme("system")
```

- `App::theme` は組織の見た目で、すべてのテーマの下に適用されます。
- `App::themes` はユーザーが選べるテーマを列挙します。指定しない場合、一覧は Light と Dark です。両方が一覧に含まれていれば System も提供されます。`Theme::named(...)` はライトテーマを土台に作られ、`.dark_base()` を付けるとダークテーマを土台にします。
- `App::default_theme` は、まだ選択していないユーザーのテーマです。指定しなければ `system` です。
- `App::theme_picker(false)` はピッカーを非表示にし、全員が既定のテーマになります。
- テーマを 1 つだけにするとアプリが固定されます。`.themes([Theme::named("acme", tokens)])` または `.theme(Theme::dark())` を使います。

トークンはアプリの起動時に検査されます。`App::check` (したがって `router` と `serve` も) は、未知のトークン名、宣言から抜け出せてしまう値 (`;`、波括弧、`\`、`<`、`>`、`url(`)、不正なテーマ名、未知の既定テーマ、そしてテーマによって WCAG 2.2 AA を下回るセクション 5 の色の組をすべて報告します。コントラストを検査できるのは `#rgb` と `#rrggbb` の値だけで、それ以外の色の記法は信頼されます。

すべてのテーマは 1 つのスタイルシート `/_zeyn/theme.css` として配信されます。このファイルは起動時に一度だけ構築され、キットのスタイルシートの後に読み込まれます。選択は `zeyn_theme` クッキーに保存され、ビューストア (`App::datagrid_views`) を持つアプリでサインイン済みのユーザーについては、そのストアにも保存されるため、新しいデバイスにも引き継がれます。サーバーは `<html>` 上にテーマを出力するので、最初の描画から正しい見た目になり、インラインスクリプトは不要です。

| マークアップ | 結果 |
|---|---|
| `<html>` | System: `prefers-color-scheme` に従う |
| `<html data-theme="light">` | 常にライト |
| `<html data-theme="dark">` | 常にダーク |
| `<html data-theme="light" data-zeyn-theme="sand">` | アプリテーマ `sand` (ライトテーマ上) |

ピッカーでテーマを変更すると、これらの属性と `color-scheme` メタが変わるだけで、その後 `POST /_zeyn/theme` が呼ばれます。再読み込みは行われません。

手書きの上書きファイルでダークテーマに独自の値を与えるには、キットが使うセレクターを繰り返し書きます。

```css
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { --z-bg: #0e1012; }
}
:root[data-theme="dark"] { --z-bg: #0e1012; }
```

### 密度

密度は 2 種類あり、トークンで切り替えます。既定はコンフォータブルで、グリッドの行が 40 px、ヘッダーが 36 px、コントロールが 36 px、カードの余白が 20 px です。コンパクト (`<html data-density="compact">`) では行、ヘッダー、コントロールが 32 px になり、余白の単位が 0.8 倍になります。ユーザーはトップバーのアカウントメニュー (`App::header(|h| h.account())`) で選びます。選択は `zeyn_density` クッキーに保存され、サーバーがそれを `<html>` に出力するため、最初の描画から正しく表示されます。コントロールとグリッドの行は 24 px より小さくならないため、コンパクトでも WCAG 2.2 のターゲットサイズを満たします。`Theme::new().compact()` を使うと、コンパクトな余白が組織の既定になります。

仮想グリッドの行の高さはサーバーが固定します。ランタイムがそこからスクロール位置を計算するためです。`Paging::virtual_scroll()` は密度に従います (コンフォータブルで 40 px、コンパクトで 32 px)。`Paging::virtual_rows(px)` は指定された高さを保ちます。密度の変更は、仮想グリッドでは次のページから反映されます。

## 3. 派生トークン

基本トークンから `color-mix()` と相対カラー構文で計算されます。基本トークンが変わると、自動的に更新されます。

|---|---|---|---|
| `--z-accent` | 面の上で文字や細い線として使うブランドカラー。リンク、現在のメニュー項目、フォーカス中の行のバー | `var(--z-brand)` | `oklch(from var(--z-brand) 0.8 c h)`。ブランドの色相を固定の明るさで使う。相対カラー構文のないブラウザーでは `color-mix(in oklab, var(--z-brand) 45%, #fff)` になる |
| `--z-primary` | プライマリボタンの塗り | `var(--z-brand)` | `var(--z-accent)` |
| `--z-on-primary` | プライマリボタンの文字 | `var(--z-on-brand)` | `#0d0f12` |
| `--z-primary-hover` | プライマリボタンのホバー | ブランド 86% に黒を混ぜた色 | アクセント 84% に白を混ぜた色 |

| `--z-brand-subtle` | 現在のメニュー項目とフォーカス中のグリッド行の背後の淡い色 | `--z-surface` の上に `--z-tint` の強さで重ねたアクセント | 同じ式 |

| `--z-ease-out`, `--z-ease-in`, `--z-ease-linear` | 表示と移動、退出、色の変化のイージング | `cubic-bezier(0.2, 0, 0, 1)`, `cubic-bezier(0.4, 0, 1, 1)`, `linear` | 同じ |

サーバーが出力するマークアップが要素ごとに設定するトークンもあります。`--z-width` (ウィンドウの幅)、`--z-flex` (列の割合)、`--z-row-height` (仮想グリッドの行の高さ)、そしてコンポーネントライブラリ用の `--z-stack-gap`、`--z-split`、`--z-progress`、`--z-columns`、`--z-level`、`--z-pop-x` / `--z-pop-y` (ポップアップの位置) です。

チャートの系列色は `components.css` の `--z-chart-1` から `--z-chart-8` で、青 `#2563d9`、オレンジ `#d67400`、マゼンタ `#a3369b`、緑 `#14866d`、オリーブ `#7a6a00`、紫 `#6e56cf`、赤 `#cc3b33`、スレート `#56636f` です。ダークテーマではより明るい値になります (`#5b9bff`、`#f08a3c`、`#e27bd6`、`#38c29f`、`#ece27a`、`#9d8cff`、`#ff7b70`、`#9aa7b5`)。この順序により、最初の 5 色は 1 型、2 型、3 型の色覚でも区別できます。また系列 1 はブランドカラーではないため、赤や緑のブランドカラーが良い値や悪い値に見えることはありません。それでもアプリで `--z-chart-1: var(--z-brand)` を設定することはできます。起動時のチェックで、それぞれ `--z-surface` に対して 3:1 を保つことを確認します。他の基本トークンと同じように上書きできます。

## 4. ブランドカラーの選び方

- ライトテーマでは、`--z-brand` の上に白い文字が載ります (プライマリボタン、ロゴの文字マーク、サインインシェルのブランドパネル)。`--z-on-brand` に対して 4.5:1 以上になる色を選んでください。中程度から濃いブランドカラーの多くは条件を満たします。黄色のように明るいブランドカラーの場合は、`--z-on-brand` も暗い色に設定してください。
- ダークテーマでは、キットは文字、リング、プライマリボタンのためにブランドカラーを明るくし、ロゴの文字マークには塗りつぶしのブランドカラーをそのまま使います。そのため、2 色目を用意しなくても、別のブランドカラーがどちらのテーマでも意図した見た目になります。
- ステータス色はブランドカラーと区別できるようにしてください。赤いブランドカラーが赤いエラー行の隣にあると、エラーを見つけにくくなります。その場合は `--z-danger` を別の赤にずらすか、`--z-brand-subtle` を上書きしてグリッドからブランドカラーを外してください。
- 色の確認には、セクション 5 の表を目標値として使ってください。基準を下回る組は WCAG 2.2 AA を満たしません。

## 6. その他のアクセシビリティ上の挙動

- すべての操作可能な要素には、`--z-focus` の色で 2 px の `:focus-visible` リングが表示されます。グリッドの行ではリングを行の内側に描画するため、スクロールコンテナーで切り取られることはありません。
- ボタン、入力欄、ソートヘッダー、フィルターボックス、ページャーボタン、ウィンドウの閉じるボタンは、どの密度でも 24 x 24 px 以上です。
- `prefers-reduced-motion: reduce` の場合、トーストの登場アニメーションとすべてのトランジションが無効になります。
- `forced-colors` モードでは、アイコンは `CanvasText` を使い、プライマリボタンとフォーカス中の行は `Highlight` を使います。背景の淡い色に頼っている状態 (現在のメニュー項目、行のステータス) には、代わりにアウトラインまたは枠線が付きます。
