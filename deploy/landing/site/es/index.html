El framework Rust para aplicaciones de negocio que escriben agentes de IA

Las personas revisan el código. El compilador y el framework lo mantienen seguro. Zeyn es de código abierto y está construido sobre axum, para aplicaciones llenas de grids, formularios y flujos de trabajo.

Errores del compilador escritos para el agente que los lee

Cada regla que el compilador puede aplicar viene con una prueba que demuestra que el código incorrecto falla y con un mensaje que dice qué cambiar. Esta es una compilación real de una acción que olvidó indicar quién puede ejecutarla.

  1. El agente escribe una acción

    Archiva un producto y pide confirmación al usuario antes, pero no declara ningún permiso.

    /// Archives a product by its code.
#[action(audit, confirm)]
pub async fn archive_product(code: String) -> Result<()> {

  2. La compilación se detiene

    El mensaje nombra el problema y las dos soluciones: añadir un permiso o marcar la acción como public.

    error: action `archive_product` has no permission
         = help: add `permission = "..."`, or `public` if this action is meant to be open to everyone
 --> src/main.rs:5:14
  |
5 | pub async fn archive_product(code: String) -> Result<()> {
  |              ^^^^^^^^^^^^^^^

  3. El agente aplica la línea de ayuda

    Ahora el servidor comprueba el permiso en cada llamada, venga de una página, de la API o de un agente.

    - #[action(audit, confirm)]
+ #[action(permission = "stock.product.write", audit, confirm)]
  pub async fn archive_product(code: String) -> Result<()> {

El mismo tipo de mensaje cubre una suma sobre una columna de texto, una clave de traducción que falta en un archivo de idioma y una acción que no devuelve un Result. Cada uno tiene una prueba compile_fail y una nota #[diagnostic::on_unimplemented].

Los agentes trabajan con los permisos del usuario que inició sesión

Agentes que usan tu aplicación

Un agente actúa como el usuario para el que trabaja. Nunca ve herramientas de pantallas o acciones que ese usuario no puede abrir.

permission = "stock.product.write"
Se comprueba en cada llamada, venga de una página, de la API o de un agente.
confirm
Un modelo solo puede ejecutar la acción después de que el usuario la confirme en la aplicación.
ai = false
La acción nunca se ofrece a un modelo.
audit
Cada llamada queda registrada y las llamadas de agentes se marcan.
Agents::read_only()
Los agentes pueden buscar pero no guardar. Elige read_write() solo cuando deban cambiar datos.

Agentes que escriben tu aplicación

zeyn new configura zeyn mcp, un servidor MCP para agentes de programación, junto a un AGENTS.md con las reglas del proyecto.

zeyn_docs
Referencia del framework por tema: reglas, lenguaje, protocolo, arquitectura
zeyn_describe
Features, pantallas, rutas, acceso, API y traducciones que faltan
zeyn_check
Compila e informa de los problemas
zeyn_test
Ejecuta las pruebas y devuelve el final de la salida
zeyn_new_feature
Crea una carpeta de feature y la registra

Un DataGrid que sigue siendo rápido con un millón de filas

El archivo de pedidos de la demo contiene un millón de pedidos. El grid los recorre con desplazamiento virtual mientras el servidor ordena, filtra y pagina. La documentación de DataGrid explica cómo.

  • Filtros tipados para cada columna
  • Totales sobre todas las filas coincidentes
  • Agrupación, árboles y maestro-detalle
  • Edición en línea con comprobación de versión de fila
  • Columnas fijas, acciones masivas, exportación a CSV y Excel

No escribes HTML, CSS ni JavaScript. Las pantallas son Rust, el servidor las renderiza y un pequeño runtime en el navegador aplica los cambios.

Qué incluye

Zeyn en conjunto está en alfa. Las partes marcadas como estables son el núcleo y las que menos probablemente cambien. Las partes experimentales funcionan y están probadas, pero espera cambios mayores entre versiones.

DataGrid Estable
Desplazamiento virtual sobre un millón de filas, filtros tipados, totales, agrupación, edición en línea, exportación a CSV y Excel
Formularios Estable
Todos los tipos de campo, validación compartida por el servidor, el navegador y la API, comprobación de conflictos por versión de fila
Acciones Estable
Entradas tipadas, una API JSON con OpenAPI y herramientas para agentes de IA que se ejecutan con los permisos del usuario
Núcleo de seguridad Estable
Permisos en cada acción, CSRF, CSP estricta, auditoría y auditoría de lectura, enmascarado de campos, límites de tasa
Bases de datos Experimental
PostgreSQL y Oracle 11g o posterior, con cursores keyset, transacciones, flujos y migraciones
Inicio de sesión y cuentas Experimental
OpenID Connect, JWT, MFA, claves de acceso y un sistema de cuentas opcional con pantallas listas
Escritorio Experimental
Un ejecutable en el WebView del sistema que funciona sin conexión
Islas WASM Experimental
Rust compilado a WebAssembly para componentes pesados, con llamadas de acción tipadas
Tiempo real Experimental
Salas WebSocket con documentos CRDT para edición en vivo, con memoria acotada
Asistente de IA Experimental
Un asistente integrado para cualquier LLM que pregunta al usuario antes de escribir

La imagen de contenedor de una aplicación generada pesa unos 43 MB y una aplicación inactiva usa unos pocos MB de memoria. Consulta Docker en la documentación de la CLI.

En qué punto está Zeyn

Zeyn es software en alfa. Lo que describe la documentación compila y está probado, pero las API aún cambian. La demo en vivo muestra dónde está hoy.

cargo install zeyn-cli
zeyn new my-app
cd my-app
cargo run

¿Trabajas con un agente de programación? Dale docs.zeynsoft.com/llms.txt. Le indica que instale la CLI, cree el proyecto y siga las reglas del proyecto.
