알파. API는 아직 바뀝니다.

AI 에이전트가 작성하는 업무용 앱을 위한 Rust 프레임워크

사람이 코드를 검토합니다. 컴파일러와 프레임워크가 안전을 지킵니다. Zeyn은 오픈 소스이며 axum 위에 만들어졌고, 그리드, 폼, 워크플로로 가득한 앱을 위한 것입니다.

문서 읽기 라이브 데모

읽는 에이전트를 위해 작성된 컴파일러 오류

컴파일러가 강제할 수 있는 모든 규칙에는 잘못된 코드가 실패함을 증명하는 테스트와 무엇을 바꿔야 하는지 알려 주는 메시지가 함께 있습니다. 다음은 누가 실행할 수 있는지 선언하는 것을 잊은 action의 실제 빌드입니다.

  1. 에이전트가 action을 작성합니다

    제품을 보관하고 먼저 사용자에게 확인을 요청하지만, 권한을 선언하지 않았습니다.

    /// Archives a product by its code.
#[action(audit, confirm)]
pub async fn archive_product(code: String) -> Result<()> {

  2. 빌드가 멈춥니다

    메시지가 문제와 두 가지 해결책을 알려 줍니다. 권한을 추가하거나 action을 public으로 표시하십시오.

    error: action `archive_product` has no permission
         = help: add `permission = "..."`, or `public` if this action is meant to be open to everyone
 --> src/main.rs:5:14
  |
5 | pub async fn archive_product(code: String) -> Result<()> {
  |              ^^^^^^^^^^^^^^^

  3. 에이전트가 help 줄을 적용합니다

    이제 서버는 호출이 페이지, API, 에이전트 중 어디에서 오든 모든 호출에서 권한을 검사합니다.

    - #[action(audit, confirm)]
+ #[action(permission = "stock.product.write", audit, confirm)]
  pub async fn archive_product(code: String) -> Result<()> {

같은 종류의 메시지가 텍스트 열에 대한 합계, 로케일 파일에 없는 번역 키, Result를 반환하지 않는 action도 다룹니다. 각각에 compile_fail 테스트와 #[diagnostic::on_unimplemented] 노트가 있습니다.

에이전트는 로그인한 사용자의 권한으로 작업합니다

앱을 사용하는 에이전트

에이전트는 자신이 대행하는 사용자로서 행동합니다. 그 사용자가 열 수 없는 Screen이나 action의 도구는 절대 보지 못합니다.

permission = "stock.product.write"
페이지, API, 에이전트 어디에서 오든 모든 호출에서 검사됩니다.
confirm
모델은 사용자가 앱에서 확인한 후에만 action을 실행할 수 있습니다.
ai = false
action은 모델에 제공되지 않습니다.
audit
모든 호출이 기록되며 에이전트의 호출은 표시됩니다.
Agents::read_only()
에이전트는 검색은 할 수 있지만 저장은 못 합니다. 데이터를 변경해야 할 때만 read_write()를 선택하십시오.

앱을 작성하는 에이전트

zeyn new는 프로젝트의 규칙이 담긴 AGENTS.md와 함께 코딩 에이전트를 위한 MCP 서버 zeyn mcp를 설정합니다.

zeyn_docs
주제별 프레임워크 레퍼런스: 규칙, 언어, 프로토콜, 아키텍처
zeyn_describe
Feature, Screen, 경로, 접근 권한, API, 누락된 번역
zeyn_check
컴파일하고 문제를 보고합니다
zeyn_test
테스트를 실행하고 출력의 끝부분을 반환합니다
zeyn_new_feature
Feature 폴더를 만들고 등록합니다

백만 행에서도 빠르게 유지되는 DataGrid

데모의 주문 아카이브에는 주문 백만 건이 있습니다. 서버가 정렬, 필터링, 페이징을 하는 동안 그리드는 가상 스크롤로 이를 훑습니다. 방법은 DataGrid 문서에서 설명합니다.

  • 모든 열에 대한 타입이 있는 필터
  • 일치하는 모든 행에 대한 합계
  • 그룹화, 트리, 마스터 디테일
  • 행 버전 검사가 있는 인라인 편집
  • 고정 열, 일괄 action, CSV 및 Excel 내보내기

HTML, CSS, JavaScript를 작성하지 않습니다. Screen은 Rust이고, 서버가 렌더링하며, 브라우저의 작은 런타임이 변경 사항을 적용합니다.

포함된 것

Zeyn은 전체적으로 알파입니다. 안정으로 표시된 부분은 코어이며 가장 바뀔 가능성이 낮습니다. 실험적인 부분은 동작하고 테스트되었지만 버전 사이에 더 큰 변경이 있을 것으로 예상하십시오.

DataGrid 안정
백만 행에 대한 가상 스크롤, 타입이 있는 필터, 합계, 그룹화, 인라인 편집, CSV 및 Excel 내보내기
폼 안정
모든 필드 타입, 서버, 브라우저, API가 공유하는 검증, 행 버전 충돌 검사
Action 안정
타입이 있는 입력, OpenAPI가 있는 JSON API, 사용자의 권한으로 실행되는 AI 에이전트용 도구
보안 코어 안정
모든 action의 권한, CSRF, 엄격한 CSP, 감사와 읽기 감사, 필드 마스킹, 속도 제한
데이터베이스 실험적
PostgreSQL과 Oracle 11g 이상, keyset 커서, 트랜잭션, 스트림, 마이그레이션
로그인과 계정 실험적
OpenID Connect, JWT, MFA, 패스키, 그리고 준비된 화면이 있는 선택적 계정 시스템
데스크톱 실험적
시스템 WebView에서 오프라인으로 동작하는 하나의 실행 파일
WASM 아일랜드 실험적
타입이 있는 action 호출과 함께 무거운 컴포넌트를 위해 WebAssembly로 컴파일된 Rust
실시간 실험적
제한된 메모리로 실시간 편집을 위한 CRDT 문서가 있는 WebSocket 룸
AI 어시스턴트 실험적
쓰기 전에 사용자에게 묻는, 모든 LLM을 위한 내장 어시스턴트

생성된 앱의 컨테이너 이미지는 약 43 MB이고, 유휴 상태의 앱은 메모리를 몇 MB만 사용합니다. CLI 문서의 Docker를 참고하십시오.

Zeyn의 현재 위치

Zeyn은 알파 소프트웨어입니다. 문서가 설명하는 것은 컴파일되고 테스트되었지만 API는 아직 바뀝니다. 라이브 데모가 현재의 상태를 보여 줍니다.

cargo install zeyn-cli
zeyn new my-app
cd my-app
cargo run

코딩 에이전트와 작업하십니까? docs.zeynsoft.com/llms.txt를 전달하십시오. 에이전트에게 CLI를 설치하고, 프로젝트를 만들고, 프로젝트의 규칙을 따르라고 알려 줍니다.
