अल्फा। API अभी बदलते रहते हैं।

AI एजेंट द्वारा लिखे जाने वाले बिज़नेस ऐप्स के लिए Rust फ्रेमवर्क

कोड की समीक्षा लोग करते हैं। कंपाइलर और फ्रेमवर्क उसे सुरक्षित रखते हैं। Zeyn ओपन सोर्स है और axum पर बना है, उन ऐप्स के लिए जिनमें ग्रिड, फ़ॉर्म और वर्कफ़्लो भरे होते हैं।

दस्तावेज़ पढ़ें लाइव डेमो कंपोनेंट

उन्हें पढ़ने वाले एजेंट के लिए लिखी गई कंपाइलर त्रुटियाँ

कंपाइलर जो भी नियम लागू कर सकता है, उसके साथ एक टेस्ट आता है जो साबित करता है कि गलत कोड विफल होता है, और एक संदेश जो बताता है कि क्या बदलना है। यह एक ऐसे action की असली बिल्ड है जिसमें यह बताना छूट गया कि उसे कौन चला सकता है।

  1. एजेंट एक action लिखता है

    यह एक उत्पाद को संग्रहित करता है और पहले उपयोगकर्ता से पुष्टि माँगता है, लेकिन कोई अनुमति घोषित नहीं करता।

    /// Archives a product by its code.
#[action(audit, confirm)]
pub async fn archive_product(code: String) -> Result<()> {

  2. बिल्ड रुक जाती है

    संदेश समस्या और दोनों समाधान बताता है: अनुमति जोड़ें, या action को public चिह्नित करें।

    error: action `archive_product` has no permission
         = help: add `permission = "..."`, or `public` if this action is meant to be open to everyone
 --> src/main.rs:5:14
  |
5 | pub async fn archive_product(code: String) -> Result<()> {
  |              ^^^^^^^^^^^^^^^

  3. एजेंट help पंक्ति लागू करता है

    अब सर्वर हर कॉल पर अनुमति जाँचता है, चाहे कॉल किसी पृष्ठ से आए, API से या किसी एजेंट से।

    - #[action(audit, confirm)]
+ #[action(permission = "stock.product.write", audit, confirm)]
  pub async fn archive_product(code: String) -> Result<()> {

इसी तरह का संदेश टेक्स्ट कॉलम पर योग, locale फ़ाइल में छूटी अनुवाद कुंजी, और ऐसे action पर भी आता है जो Result नहीं लौटाता। हर एक के लिए एक compile_fail टेस्ट और एक #[diagnostic::on_unimplemented] टिप्पणी है।

एजेंट साइन इन उपयोगकर्ता की अनुमतियों के साथ काम करते हैं

आपका ऐप इस्तेमाल करने वाले एजेंट

एजेंट उसी उपयोगकर्ता की तरह काम करता है जिसके लिए वह काम करता है। उसे उन स्क्रीन या action के टूल कभी नहीं दिखते जिन्हें वह उपयोगकर्ता नहीं खोल सकता।

permission = "stock.product.write"
हर कॉल पर जाँची जाती है, चाहे पृष्ठ से हो, API से या एजेंट से।
confirm
मॉडल action तभी चला सकता है जब उपयोगकर्ता ऐप में उसकी पुष्टि कर दे।
ai = false
action मॉडल को कभी नहीं दिया जाता।
audit
हर कॉल दर्ज होती है, और एजेंट की कॉल चिह्नित होती हैं।
Mcp::read_only()
एजेंट खोज सकते हैं लेकिन सहेज नहीं सकते। read_write() तभी चुनें जब उन्हें डेटा बदलना हो।

आपका ऐप लिखने वाले एजेंट

zeyn new कोडिंग एजेंट के लिए MCP सर्वर zeyn mcp सेट करता है, साथ में प्रोजेक्ट के नियमों वाली AGENTS.md भी।

zeyn_docs
विषय के अनुसार फ्रेमवर्क संदर्भ: नियम, भाषा, प्रोटोकॉल
zeyn_describe
Feature, स्क्रीन, रूट, एक्सेस, API और छूटे हुए अनुवाद
zeyn_check
कंपाइल करता है और समस्याएँ बताता है
zeyn_test
टेस्ट चलाता है और आउटपुट का अंत लौटाता है
zeyn_new_feature
feature फ़ोल्डर बनाता है और उसे पंजीकृत करता है

दस लाख पंक्तियों पर भी तेज़ रहने वाला DataGrid

डेमो के ऑर्डर संग्रह में दस लाख ऑर्डर हैं। ग्रिड वर्चुअल स्क्रॉलिंग से उनमें स्क्रॉल करता है, जबकि सर्वर क्रम, फ़िल्टर और पृष्ठ संभालता है। DataGrid दस्तावेज़ बताते हैं कि यह कैसे होता है।

  • हर कॉलम के लिए टाइप्ड फ़िल्टर
  • सभी मेल खाने वाली पंक्तियों पर योग
  • समूहन, ट्री और master detail
  • पंक्ति संस्करण जाँच के साथ इनलाइन संपादन
  • पिन किए गए कॉलम, थोक कार्रवाइयाँ, CSV और Excel निर्यात

आप कोई HTML, CSS या JavaScript नहीं लिखते। स्क्रीन Rust में होती हैं, सर्वर उन्हें रेंडर करता है, और ब्राउज़र में एक छोटा रनटाइम बदलाव लागू करता है।

पैकेज में क्या है

Zeyn पूरा अल्फा है। स्थिर चिह्नित हिस्से कोर हैं और उनके बदलने की संभावना सबसे कम है। प्रायोगिक हिस्से काम करते हैं और टेस्ट किए गए हैं, लेकिन संस्करणों के बीच बड़े बदलाव की अपेक्षा रखें।

DataGrid स्थिर
दस लाख पंक्तियों पर वर्चुअल स्क्रॉलिंग, टाइप्ड फ़िल्टर, योग, समूहन, इनलाइन संपादन, CSV और Excel निर्यात
Forms स्थिर
हर फ़ील्ड प्रकार, सर्वर, ब्राउज़र और API में साझा सत्यापन, पंक्ति संस्करण टकराव जाँच
Actions स्थिर
टाइप्ड इनपुट, OpenAPI वाली JSON API, और उपयोगकर्ता की अनुमतियों के साथ चलने वाले AI एजेंट के टूल
सुरक्षा कोर स्थिर
हर action पर अनुमतियाँ, CSRF, सख़्त CSP, ऑडिट और पठन ऑडिट, फ़ील्ड मास्किंग, दर सीमाएँ
डेटाबेस प्रायोगिक
PostgreSQL, और Oracle 11g या बाद का संस्करण, keyset कर्सर, ट्रांज़ैक्शन, स्ट्रीम और माइग्रेशन के साथ
साइन इन और खाते प्रायोगिक
OpenID Connect, JWT, MFA, passkey, और तैयार स्क्रीन वाला वैकल्पिक खाता सिस्टम
डेस्कटॉप प्रायोगिक
सिस्टम WebView में चलने वाली एक एक्ज़ीक्यूटेबल, जो ऑफ़लाइन काम करती है
WASM islands प्रायोगिक
भारी कंपोनेंट के लिए WebAssembly में कंपाइल किया गया Rust, टाइप्ड action कॉल के साथ
रीयलटाइम प्रायोगिक
लाइव संपादन के लिए CRDT दस्तावेज़ों वाले WebSocket रूम, सीमित मेमोरी के साथ
AI असिस्टेंट प्रायोगिक
किसी भी LLM के लिए एम्बेडेड असिस्टेंट, जो लिखने से पहले उपयोगकर्ता से पूछता है

जनरेट किए गए ऐप की कंटेनर इमेज लगभग 43 MB की है, और निष्क्रिय ऐप कुछ MB मेमोरी लेता है। देखें CLI दस्तावेज़ में Docker।

Zeyn की मौजूदा स्थिति

Zeyn अल्फा सॉफ़्टवेयर है। दस्तावेज़ जो बताते हैं वह कंपाइल होता है और टेस्ट किया गया है, लेकिन API अभी बदलते हैं। लाइव डेमो दिखाता है कि आज यह कहाँ तक पहुँचा है।

cargo install zeyn-cli
zeyn new my-app
cd my-app
cargo run

कोडिंग एजेंट के साथ काम कर रहे हैं? उसे docs.zeynsoft.com/llms.txt दें। यह एजेंट को CLI इंस्टॉल करने, प्रोजेक्ट बनाने और प्रोजेक्ट के नियम मानने को कहता है।
