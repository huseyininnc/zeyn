The Rust framework for business apps that AI agents write

People review the code. The compiler and the framework keep it safe. Zeyn is open source and built on axum, for apps full of grids, forms and workflows.

Compiler errors written for the agent that reads them

Every rule the compiler can enforce comes with a test that proves the wrong code fails, and a message that says what to change. This is a real build of an action that forgot to say who may run it.

  1. The agent writes an action

    It archives a product and asks the user to confirm first, but it declares no permission.

    /// Archives a product by its code.
#[action(audit, confirm)]
pub async fn archive_product(code: String) -> Result<()> {

  2. The build stops

    The message names the problem and both fixes: add a permission, or mark the action public.

    error: action `archive_product` has no permission
         = help: add `permission = "..."`, or `public` if this action is meant to be open to everyone
 --> src/main.rs:5:14
  |
5 | pub async fn archive_product(code: String) -> Result<()> {
  |              ^^^^^^^^^^^^^^^

  3. The agent applies the help line

    Now the server checks the permission on every call, whether it comes from a page, the API or an agent.

    - #[action(audit, confirm)]
+ #[action(permission = "stock.product.write", audit, confirm)]
  pub async fn archive_product(code: String) -> Result<()> {

The same kind of message covers a sum on a text column, a translation key missing from a locale file, and an action that does not return a Result. Each one has a compile_fail test and a #[diagnostic::on_unimplemented] note.

Agents work with the signed in user's permissions

Agents that use your app

An agent acts as the user it works for. It never sees tools for screens or actions that user may not open.

permission = "stock.product.write"
Checked on every call, from a page, the API or an agent.
confirm
A model may run the action only after the user confirms it in the app.
ai = false
The action is never offered to a model.
audit
Every call is recorded, and agent calls are marked.
Mcp::read_only()
Agents can search but not save. Choose read_write() only when they should change data.

A DataGrid that stays fast at a million rows

The demo's order archive holds one million orders. The grid scrolls through them with virtual scrolling while the server sorts, filters and pages. The DataGrid docs explain how.

  • Typed filters for every column
  • Totals over all matching rows
  • Grouping, trees and master detail
  • Inline editing with row version checks
  • Pinned columns, bulk actions, CSV and Excel export

You write no HTML, CSS or JavaScript. Screens are Rust, the server renders them, and a small runtime in the browser applies the changes.

What is in the box

Zeyn is alpha as a whole. Parts marked stable are the core and the least likely to change. Experimental parts work and are tested, but expect bigger changes between versions.

DataGrid Stable
Virtual scrolling over a million rows, typed filters, totals, grouping, inline editing, CSV and Excel export
Forms Stable
Every field type, validation shared by the server, the browser and the API, row version conflict checks
Actions Stable
Typed inputs, a JSON API with OpenAPI, and tools for AI agents that run with the user's permissions
Security core Stable
Permissions on every action, CSRF, strict CSP, audit and read audit, field masking, rate limits
Databases Experimental
PostgreSQL, and Oracle 11g or later, with keyset cursors, transactions, streams and migrations
Sign in and accounts Experimental
OpenID Connect, JWT, MFA, passkeys, and an optional accounts system with ready screens
Desktop Experimental
One executable in the system WebView that works offline
WASM islands Experimental
Rust compiled to WebAssembly for heavy components, with typed action calls
Realtime Experimental
WebSocket rooms with CRDT documents for live editing, with bounded memory
AI assistant Experimental
An embedded assistant for any LLM that asks the user before it writes

A generated app's container image is about 43 MB, and an idle app uses a few MB of memory. See Docker in the CLI docs.

Where Zeyn stands

Zeyn is alpha software. What the docs describe compiles and is tested, but APIs still change. The live demo shows where it stands today.

cargo install zeyn-cli
zeyn new my-app
cd my-app
cargo run

Working with a coding agent? Give it docs.zeynsoft.com/llms.txt. It tells the agent to install the CLI, create the project and follow the project's rules.
